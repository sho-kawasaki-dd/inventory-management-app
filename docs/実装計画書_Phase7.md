## 1. 目的

- 品目を複数選択して、エーワン 72212(A4 12 面)の棚ラベルを印刷できるようにする。使いかけの用紙にも、1 枚目の印字位置と品目ごとの枚数を指定して印刷できるようにする(開発計画書 9.1)。
- 一覧の現在の絞り込み結果を、A4 横の在庫表として印刷できるようにする(開発計画書 9.1)。
- プリンタ差・用紙差による印字ずれを、設定ダイアログの補正値で現場調整できるようにする。
- 完了条件(開発計画書 9 章): 実用紙への試し刷りで位置ずれが許容範囲内であること。

## 2. 要件

### 2.1 満たすべき仕様

- 開発計画書 6.2(メニュー・ツールバー)、6.3(印刷プレビュー・設定ダイアログ)、9.1(印刷の基本設計)、8 章(印刷は手動チェックリスト、面付けは Qt 非依存の純関数テスト)に従う。
- 棚ラベル:
  - 用紙は A4 縦、2 列×6 段、ラベル 86.4mm × 42.3mm。寸法は `LabelSpec` に集約する(左余白 18.6mm、上余白 21.6mm、横ピッチ 86.4mm、縦ピッチ 42.3mm の推定値)。
  - 印字項目は品名・管理番号・保管場所・備考(メーカー型番・用途は印字しない)。各項目は `QFontMetrics.elidedText` で描画幅を基準に切り捨てる。
  - 面付け: 品目の並びは一覧の表示順。品目ごとに 1〜99 枚(既定 1)。1 枚目は 12 個のチェックで使用位置を指定(既定は全オン)し、左→右、上→下の順に割り当てる。1 枚目に収まらない分は 2 枚目以降へ送り、2 枚目以降は常に全 12 面を使う。すべてオフでは印刷できない。チェック状態は保存せず、開くたびに全オンへ戻す。
  - 座標は mm 単位で計算し、`QPrinter` の解像度に依存させない。`QPageLayout` の余白は 0、フルページ指定で紙端基準に描画する。
- 在庫表:
  - A4 横。列は 管理番号・品名・メーカー型番・用途・カテゴリ・保管場所・数量・単位・閾値・推奨発注数・低在庫・発注主体 の 12 列。行は一覧の現在の表示順(ソート反映)。
  - 改ページ時は見出し行を繰り返す。フッタに印刷日時(OS ローカル時刻)とページ番号を出す。
  - 行と条件要約は、最後に一覧取得が成功した時点の状態から作る。検索の遅延更新待ちや取得失敗時に、入力中の条件を表示中の行と組み合わせない。
- 印刷は `QPrintPreviewDialog` を継承した共通クラス経由とする。A4・所定の向き・余白 0・フルページは変更させず、各描画開始前にも再設定・検証する。ネットワーク通信は行わない(開発計画書 7.4)。
- プレビューは常に全ページを表示し、実印刷だけ印刷ダイアログで指定したページ範囲を反映する。範囲印刷でも面付けをやり直さず、在庫表のフッタは元文書のページ番号・総ページ数を維持する。
- 文字幅はフォント設定後の `painter.fontMetrics()` で測定し、`elidedText` の幅と描画座標を同じデバイス単位にそろえる。`QPainter.begin()`・`device.newPage()`・`QPainter.end()` の失敗を戻り値で検知する。
- 印刷操作全体と `paintRequested` のコールバック内をそれぞれ `run_guarded` で包む。描画失敗後は同じ印刷操作の再描画・印刷を続行せず、ログと汎用エラーダイアログで一度だけ通知して中断する。
- `core/`・`db/` は変更しない(印刷は UI 層の機能)。`ui/printing/layout.py` は PySide6 を import しない。
- UI は Service のみを呼ぶ。印刷に必要なデータは既存の `ItemRow`(`InventoryService.list_items()` の結果)で足りる。
- 次のコマンドがローカル(Windows)と CI(Windows/Linux)で成功する。
  - `uv sync --locked`
  - `uv run ruff check` / `uv run ruff format --check`
  - `uv run pyright`(`core/`・`db/` は strict、`ui/` ほかは standard でエラー 0 件)
  - `uv run pytest --cov`(Linux は `QT_QPA_PLATFORM=offscreen`)
  - `uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90`
- テストで実プリンタ・実データの保存先(`%APPDATA%` 等)を使用しない。PDF は `tmp_path` に出力し、共通プレビュークラスと `QPrintDialog` の `exec`・メッセージボックスは必要に応じて差し替える。コールバックの異常系は Qt のシグナルを実際に発火させ、単なる Python 関数呼び出しだけで代替しない。

### 2.3 決定事項

| 項目 | 決定 |
| --- | --- |
| PR 分割 | 7a(計画書・正本同期・一覧の複数選択化・面付け純関数・補正値・共通プレビュー制御・棚ラベルのダイアログと描画・導線)→ 7b(在庫表・一覧と条件の一体保存・手動チェック・文書同期)の 2 PR。各 PR は CI 成功後にマージし、7b は 7a のマージ後の最新の `main` から作成する |
| 複数選択 | 一覧を `ExtendedSelection` に変更する。編集・廃止/再有効化・在庫操作・履歴・販売ページを開くは、ちょうど 1 件選択時のみ活性にする(0 件・複数件では不活性)。ダブルクリックでの履歴表示、低在庫ドックからの選択(1 件選択)は従来どおり動かす。再描画(`refresh`・`refresh_items`)後は選択中の品目 ID 集合を可能な限り復元する |
| ラベルの並び順 | 一覧の表示順(ソート反映)。選択した順序には依存させない。Shift 範囲選択でも結果が決定的になる |
| 面付けの配置 | `LabelSpec`・面付け純関数・在庫表の列定義・ページ分割は `ui/printing/layout.py` に置き、Qt を import しない(pyright は `ui/` の standard)。`core/` には置かない |
| 位置補正 | `ui_settings.json` に `label_offset_left_mm`・`label_offset_top_mm`(float、−10.0〜+10.0、0.1 刻み、正は右・下へ移動)を追加し、設定ダイアログの「棚ラベル印字位置の補正」で調整する。端末ごとのプリンタ差を扱うため DB・バックアップ・復元の対象外(開発計画書 5.9 の UI 表示設定と同じ扱い)。ファイルなし・型不正・bool・非有限・範囲外は項目ごとに 0.0 へフォールバックしログに警告する |
| 「既定に戻す」 | フォント・文字サイズのみを既定に戻す。補正値は戻さない(実測値の誤消去を防ぐ)。補正値は OK で他の表示設定と同時に保存し、次回の印刷から反映する |
| 印刷用フォント | UI のフォント設定に依存させず、印刷用に固定する(開発計画書 10 章のリスク対策)。候補は `Yu Gothic UI`・`Meiryo UI`・`Noto Sans CJK JP` の順で `QFontDatabase.families()` に存在する最初のもの、なければ `QFontDatabase.systemFont(GeneralFont)`。サイズは pt 固定で、文字サイズ倍率の影響を受けない |
| ラベルの描画 | ラベル内側の余白 3mm。4 行を上から、品名(太字 11pt)、管理番号(太字 14pt)、保管場所(10pt)、備考(9pt)で描く。各行は 1 行で `elidedText(ElideRight)` とし、備考中の改行は空白に置換する。空の項目は空白行のまま(詰めない)。フォントサイズ・行位置は試し刷りで調整可能な定数として `LabelSpec` ではなく描画モジュールにまとめる。オフにした位置は何も描かない。枠線は描かない(用紙に印刷済み) |
| 廃止品目 | 棚ラベルは印刷可(選択のみ条件とする)。在庫表は一覧に表示されている行(「廃止品目を含む」のときだけ廃止品目が含まれる)を出力し、品名に「(廃止)」を付ける |
| 在庫表の列 | 管理番号・品名・メーカー型番・用途・カテゴリ(フルパス)・保管場所・数量・単位・閾値・推奨発注数・低在庫(○)・発注主体。数値は右寄せ・3 桁区切り。幅の初期値(mm、合計 277 = A4 横 297 − 左右余白 10mm × 2): 管理番号 22 / 品名 46 / メーカー型番 32 / 用途 32 / カテゴリ 36 / 保管場所 26 / 数量 13 / 単位 9 / 閾値 13 / 推奨発注数 17 / 低在庫 12 / 発注主体 19。セルは 1 行で `elidedText` により切り捨てる |
| 在庫表のレイアウト | タイトル「在庫表」と件数、現在の絞り込み条件の要約(検索語・クライアント・発注主体・カテゴリ・保管場所・低在庫のみ・廃止品目を含む。条件なしは「(絞り込みなし)」)を 1 ページ目の上部に置く。タイトル領域の高さを固定寸法(25mm)として定義し、1 ページ目の明細行数を条件要約の長さに依存しない定数として計算する。見出し行は全ページで繰り返す。フッタは左に印刷日時(`timeutil.format_local(utc_now_str())`)、右に「ページ n / N」。1 ページの行数は行高(mm)から計算する |
| 一覧と条件の一体保存 | `refresh_items()` の取得成功時だけ、表示する行・適用済み `ItemFilter`・条件の表示名を一緒に更新する。初回取得成功前は表示済み結果なしとして扱う。在庫表は最後に取得成功した状態から表示順の行・条件要約・印刷日時をまとめてスナップショット化する。検索の遅延更新待ちや取得失敗時に `_current_item_filter()` と現在のコンボ表示名を読み直さず、印刷のための再取得もしない |
| 在庫表 0 件 | 一覧が 0 件のときは「印刷する品目がありません」を表示してプレビューを開かない |
| 導線 | ファイルメニューの「印刷」サブメニュー(棚ラベル・在庫表)、ツールバー出力グループの「印刷」ドロップダウン(同じ 2 つの `QAction` を共有)、一覧の右クリックメニューに棚ラベルを追加する。棚ラベルは 1 件以上選択時のみ活性、在庫表は常時活性。右クリックの棚ラベルは参照グループの後に区切り線付きで置く |
| プレビュー | `ui/printing/preview_dialog.py` に `QPrintPreviewDialog` を継承する `PrintPreviewDialog` を置き、7a で実装して 7b で再利用する。`QPrinter(HighResolution)` を使い、`paintRequested` でスナップショットを描画する。標準の縦横切替・ページ設定操作は非表示または無効化し、標準の印刷操作も共通クラスが管理する独自操作に置き換える(実印刷は `preview.print_()` を経由せず、`QPrintDialog` 成功後に実プリンタへ直接描画コールバックを呼ぶ)。Qt 内部の UI 構造へのアクセスはこのモジュールに限定し、固定している Qt バージョンで操作の識別・無効化をテストする。表示は `dialog_placement` の既存の配置規則に合わせる(1366×768 で作業領域に収める) |
| 用紙設定の固定 | プレビュー描画時と、`QPrintDialog` でプリンタ選択後の実印刷時の両方で、`QPainter.begin()` 前に A4・所定の向き(棚ラベル: 縦、在庫表: 横)・余白 0・フルページを再設定し、設定結果と実際の `pageLayout()`・`fullPage()` を検証する。プリンタ変更・設定変更で固定条件を満たせない場合は、描画を開始せず通知して中止する。在庫表の 10mm は紙端からの描画上の余白とし、プリンタ余白に重ねて設定しない |
| ページ範囲 | 共通クラスがプレビューと実印刷を明示的に区別する。プレビューは範囲指定に関係なく全ページ。実印刷は `QPrintDialog` で全ページまたはページ範囲を指定でき、選択範囲・現在のページ指定は無効化する。`printRange()` と `pageRanges()`(必要時は `fromPage()`・`toPage()`)から元文書の対象ページ番号を求める。番号は 1 始まり、全ページは `page_numbers=None`、範囲指定は昇順の重複なしの番号列として両レンダラーへ渡す。不正な範囲・対象ページなしは描画前に拒否する。面付け・ページ分割をやり直さず、元の位置番号とフッタ「ページ n / N」を維持する。最初に出力するページの前や最後のページの後に `newPage()` を呼ばない |
| 描画コールバックの失敗 | 印刷操作全体に加え、`paintRequested` に接続するコールバック内も `run_guarded` で包む。失敗フラグで同じ操作の再描画・印刷を防ぎ、通知は一度だけとする。レンダラーの終了処理後、コールバックから戻ってからプレビューを終了する(`QTimer.singleShot(0, self.reject)` による遅延クローズで描画イベント処理中の破壊を防ぐ)。実印刷の失敗時は `QPrinter.abort()` による中止を試みるが、送信・印刷済みページの取り消しは保証しない。外側の `exec()` の例外捕捉やグローバル例外フックに描画失敗の処理を委ねない |
| 文字幅測定 | 各行・セルの `painter.setFont()` 後に `painter.fontMetrics()` を取得する。デバイスを指定しない `QFontMetrics(font)` は使わない。内側余白を除いた幅を `logicalDpiX()` でデバイス座標へ変換し、整数幅へ切り下げて `elidedText` に渡す。フォントを変えたらメトリクスも取得し直し、mm とデバイス座標を混在させない |
| 描画デバイスの失敗 | `QPainter.begin()`・`device.newPage()`・`QPainter.end()` の戻り値を検査し、`False` は印刷失敗として例外で通知する。開始成功後は例外の有無にかかわらず `try/finally` で終了処理する。元の描画例外がある場合、終了処理の失敗はログに残し、元の例外を上書きせず一度だけ通知する。開始失敗・対象ページなしでは描画を続けない |
| 印刷設定ダイアログ(棚ラベル) | 品目表(管理番号・品名・枚数 `QSpinBox` 1〜99 既定 1)、2 列×6 段の位置チェック 12 個(用紙の配置どおりに並べる)、「すべて選択」「すべて解除」、「合計 N 枚 / 用紙 M 枚」の表示。すべてオフのときは OK を不活性にし理由を表示する。品目表と位置チェックが縦に収まらない場合に備え `QScrollArea` を使い、文字サイズ 150% でも 1366×768 に収める |
| 単位 | 長さは mm の `float` で持ち、デバイス座標への変換は描画側で `mm / 25.4 * dpi` とする。ラベルの寸法・余白・ピッチは `LabelSpec` のみに定義し、他に直書きしない |

### 2.4 対象外

- バーコード・QR コードの印字
- 棚ラベル以外の用紙(別型番のラベルシール、用紙サイズの選択)と、`LabelSpec` の UI での編集(余白・ピッチは補正値と実測後のコード修正で対応する)
- 印刷設定(枚数・位置チェック)の保存
- 在庫表の列の選択・並べ替え、条件指定による在庫表の再取得(画面の一覧の絞り込み結果のみを出力する)
- プレビューを経由しない直接印刷、PDF への直接保存メニュー(プレビューダイアログ内の印刷機能は利用可)
- 履歴・ダッシュボードの印刷
- パッケージング(Phase 8)

## 5. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 一覧の複数選択化で、単一選択前提の処理が複数選択時に誤動作する | 誤った品目への編集・在庫操作 | `_selected_item_id()` を「ちょうど 1 件のみ」に変更し、呼び出し元をすべて確認する。複数選択時に各操作が不活性になること、`refresh` 後の選択復元をテストで固定する |
| 余白・ピッチが推定値のため印字がずれる | ラベルの枠から文字がはみ出す | 補正値(±10mm)で現場調整できるようにし、手動確認 #1・#6・#7 で実測する。確定した値は `LabelSpec` と正本 9.1 に反映する |
| プリンタごとの非印字領域・フルページ指定の挙動差 | 用紙端のラベルが欠ける、位置が全体的にずれる | `QPageLayout` の余白 0 とフルページ指定で紙端基準にし、ずれは補正値で吸収する。手動確認 #7 で四隅を確認し、解消できない機種は制約として記録する |
| 印刷用フォントの欠落(Linux・別 PC)による文字化け・サイズ変動 | 切り捨て位置が変わる | 候補リスト→システム既定の順でフォールバックし、`elidedText` で実測幅を基準に切り捨てる。UI の倍率に依存させない |
| 標準プレビュー・印刷ダイアログで用紙設定が変わる | 固定座標のラベル・在庫表が欠ける | H0 で変更操作を制限し、プリンタ選択後も含む各描画前に設定を再固定・検証する。満たせなければ開始せず中止する |
| Qt 内部の UI 構造がバージョン更新で変わる | 用紙変更の制限や独自の印刷操作が効かない | 内部 UI へのアクセスは `preview_dialog.py` だけに限定し、固定 Qt バージョンで操作識別をテストする。Qt 更新時も同じ検査を必須とする |
| 印刷ダイアログのページ範囲を描画側が無視する | 指定外ページの出力、ラベル用紙の無駄 | H0 でプレビューと実印刷を区別し、実印刷の対象ページだけを元の面付け・ページ分割から抽出する。番号を詰め直さず、先頭・末尾の空白ページを防ぐ |
| 画面向けの文字幅とプリンタの DPI が混在する | 省略されない文字が枠・セルからはみ出す | フォント設定後の `painter.fontMetrics()` と描画先のデバイス幅を使う。300 DPI・1200 DPI で省略後の幅を検証する |
| 検索の遅延更新待ち・一覧取得失敗時に入力中の条件を読む | 在庫表の内容と条件要約が食い違う | M で取得成功時の行・適用済み条件・表示名を一体で保存し、印刷時にはその状態だけを使う。取得失敗では両方を維持する |
| `paintRequested` が複数回呼ばれ、描画中に一覧が更新される | プレビューと印刷結果が食い違う | H・M で行・面付け・補正値、在庫表の条件要約・印刷日時をプレビュー開始時点に固定する。描画関数はスナップショットだけを参照する |
| 在庫表で品目数が多く(5,000 件)プレビューの再描画が遅い | プレビューが固まる | 4.1 で所要時間を記録する。許容できない場合は、描画をページ単位に分割してプレビューの要求に応じて必要なページのみ描く方式を別途検討する(本フェーズでは目標値を設けず記録のみ) |
| シグナル内の描画例外が外側の `run_guarded` に伝わらない | 失敗後も印刷を続行する、エラー通知が重複する | H0 の描画コールバック内を `run_guarded` で包み、失敗フラグで後続処理を停止する。通知は一度だけにし、コールバックから戻ってからプレビューを終了する(`QTimer.singleShot(0, self.reject)` による遅延クローズで描画イベント中の破棄を防止) |
| 描画開始・改ページ・終了が例外なしで失敗する | 空の出力、途中までの印刷を成功扱いする | F・L で戻り値を検査して例外で通知する。開始成功後の終了処理を保証し、終了失敗で元の例外を上書きしない。実印刷では中止を試みるが、送信・印刷済みページの取り消しは保証しない |
| 補正値の入力が不正(手編集された JSON など) | 描画位置が用紙外になる | 項目ごとに範囲・型・有限性を検証し、不正なら 0.0 へフォールバックする(D)。範囲は ±10mm に限定する |
| 面付けのロジックを UI と混在させ、テストが Qt に依存する | テストの低速化・不安定化 | 面付け・座標・ページ分割・値の整形は Qt 非依存の `layout.py` に集約し、依存ルールのテストで Qt の import を禁止する |
| 開発計画書と実装がずれる | 後続フェーズの基準が曖昧になる | A で 7a の仕様変更を実装前に同期し、O で 7b の仕様・実測値を同期する |
