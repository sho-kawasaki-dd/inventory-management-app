## 1. 目的

- クライアント・発注主体を独立に絞り込み、年度・月ごとの入庫数・出庫数・支出額(出庫基準。FIFO 原価)を、グラフと内訳表で確認できるようにする(開発計画書 5.7)。
- 内訳軸(なし / クライアント別 / 発注主体別 / クライアント×発注主体)を切り替え、廃棄数・廃棄額と単価未登録数量を別枠で確認できるようにする。
- 表示中の集計を CSV、グラフを PNG で出力できるようにする(開発計画書 5.8)。
- 品目 5,000 件・履歴 100,000 件でも、ダッシュボードの集計を 2 秒以内で表示する(開発計画書 7.5)。

## 2. 要件

### 2.1 満たすべき仕様

- 開発計画書 5.7(ダッシュボード集計)、5.8(CSV)、6.3(Dashboard)、6.4(表示要件)、7.5(性能)に従う。
- 完了条件(開発計画書 9 章): 5.7 の集計がテストデータと一致する。CSV / PNG を出力できる。
- `core/` と `db/` は PySide6 を import しない。UI は `sqlite3`・`inventory_manager_mini.db` を import せず、Service のみを呼ぶ。
- 集計値は Python の任意精度整数で計算し、5.2.1 の集計上限で検証する。SQL の `SUM` に依存せず、列名を文字列で組み立てない。
- 期間境界はローカル暦を `core/timeutil.py` で UTC に変換し、半開区間 `[start, end)` で判定する。取り消し行は元行の `moved_at` で期間判定する。
- 年度は開始年で表す。開始月を `s` とすると、年度 `y` の期間は `[y年s月1日, (y+1)年s月1日)` とする(開発計画書 5.7)。年度列挙・現在年度・月次/年次集計の定義を統一する。
- 内訳軸によらず、同一の絞り込み条件の合計は一致する。返品・棚卸(初期数量を含む)は集計に含めない。
- 無効化済みのクライアント・発注主体も、過去履歴の集計対象として選択肢に含める。
- 1366×768 で全体が作業領域に収まり、文字サイズ 150% でも同様とする(開発計画書 6.4)。
- 次のコマンドがローカル(Windows)と CI(Windows/Linux)で成功する。
  - `uv sync --locked`
  - `uv run ruff check` / `uv run ruff format --check`
  - `uv run pyright`(`core/`・`db/` は strict、`ui/` ほかは standard でエラー 0 件)
  - `uv run pytest --cov`(Linux は `QT_QPA_PLATFORM=offscreen`)
  - `uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90`
- テストで実データの保存先(`%APPDATA%` 等)を使用しない。ファイル選択ダイアログ・メッセージボックスはテストで差し替える。

| 年次表示 | 全年度の推移。`available_fiscal_years()` の全年度を 1 年度 1 区間で並べる。年度選択は月次のときだけ有効にする(年次では無効化) |

| グラフ構成 | 数量グラフ(入庫数・出庫数の棒)と金額グラフ(支出額の棒)を上下に配置する。単位が異なる指標を 1 つの軸に混在させない。縦軸は 0 始まりで、全値が 0 のときは 0〜1 とする。縦軸の上限と目盛り間隔は、間隔を 1・2・5 × 10^n のうち「最大値 ÷ 5 以上」を満たす最小の候補とし、上限を最大値以上の最小の間隔の倍数とする(整数目盛り、0 を含め最大 6 本、数量・金額の軸は独立)。棒にカーソルを合わせると、期間・系列名・値(3 桁区切り、金額は「円」付き)をツールチップで表示し、外れると消す(表示値は集計結果そのもので、軸の丸めによらない)。グラフは絞り込み結果の合計(内訳軸によらない)を表示し、内訳は表で確認する。カテゴリ軸はラベルの重なりを防ぐため斜め(-45度)に傾けて表示する。チャート更新は方式B(新しい `QChart` を生成して `setChart` で差し替え、旧チャートを確実に解放)を採用し、差分更新特有のラベル描画ズレを防ぎメモリを確実に解放する。`setChart` が旧チャートを自動削除するかは実装前に実機で確認し(D)、`deleteLater()` の二重解放を避ける。グラフタブは `QScrollArea`(`setWidgetResizable(True)`)内に 2 つの `QChartView` を縦に並べたコンテンツウィジェットを置き、各チャートの最小高さは `fontMetrics().height()` に比例させてフォントに追従させる |
| 画面構成 | 上段に絞り込み(クライアント・発注主体・年度・年次/月次・内訳軸)、合計ラベル、`QTabWidget`(「グラフ」「内訳」「廃棄」)、下段に CSV 出力・PNG 保存・閉じる。「内訳」は入庫数・出庫数・支出額・単価未登録数量、「廃棄」は廃棄数・廃棄額。画面の「廃棄」表は廃棄実績のある行(廃棄数 > 0 または 廃棄額 > 0)のみを表示し、実績のない行は除外して一覧性を保つ(CSV は 5.8 どおり全行を出力する) |
| 集計 API | `ReportService.dashboard_result()` が「期間ごとの合計(全期間を 0 で埋める)」と「内訳軸の行」を 1 回の SQL・1 回の走査で返す。内訳軸がある場合も集計を 2 回に分けない。既存の `dashboard()` は互換のため残し、内訳行を返す |
| 年次の引数 | `dashboard_result(fiscal_year=None, ANNUAL)` で全年度の推移。`fiscal_year=None` と `MONTHLY` の組み合わせは `ValueError`。年度の列挙と集計は同じ読み取りトランザクション内で行う |
| 絞り込み軸の行キー | 内訳軸に含まれない軸でも、その軸で絞り込み中なら行の ID・名称に絞り込み対象を設定する。未絞り込みの軸だけ `None`(CSV では「(すべて)」)。存在しない ID は `ValidationError` |
| ダッシュボード CSV | 画面に表示中の内訳行をそのまま出力する(再集計しない)。`export_dashboard_csv(path, rows)` とし、列は開発計画書 5.8 の 9 列。畳み込んだ軸は未絞り込みなら「(すべて)」、絞り込み中ならその名称を出力する。開発計画書 5.8 にこの規則を追記する |
| PNG | 集計取得済みかつグラフタブ表示中のみ活性。数量・金額の 2 グラフを含む全コンテンツウィジェットを `grab()` で 1 枚に保存する。スクロール対応時も viewport ではなく内部の全コンテンツを取得し、スクロール位置によらず両グラフを欠けなく保存する。`QSaveFile` に書いて `commit()` し、失敗時は既存ファイルを壊さず `FileOutputError` を発生させる |
| 保存先の選択 | `ui/csv_export.py` の保存先選択(拡張子補完・補完後の上書き確認)を拡張子・既定名・フィルタを受け取る汎用関数にし、CSV と PNG で共用する。既存 CSV の挙動は変えない |
| 再集計のタイミング | 条件変更時は即時に再集計する(待機カーソル、`run_guarded` 内)。`data_changed` は、表示中のみ `QTimer` の単発タイマー(連続発火をまとめる)で再集計し、非表示中は「古い」印だけ付けて次の `showEvent` で再集計する。`showEvent` は「古い」印があるとき(初期状態を含む)だけ再集計し、最小化からの復帰(spontaneous)では再集計しない。再集計時は年度とマスタの選択肢を読み直し、選択中の値は可能な限り維持する |
| 通常の閉じる操作 | 「閉じる」ボタン・ウィンドウの ×・`hide()` はいずれも非表示にするだけでインスタンスを保持する。非表示時の処理は `closeEvent` ではなく `hideEvent`(最小化による spontaneous なものは除く)で行い、予約済みの再集計タイマーが動いていれば停止して「古い」印を付ける。タイマーが動いていなければ印は付けず、非表示中の `data_changed` でのみ印を付ける(`hide()` → `show()` だけでは再集計しない)。再集計コールバックは非表示中または終了状態なら Service を呼ばない |
| 復元・終了との関係 | 復元の上書きを始める前と MainWindow の新設 `closeEvent` で `DashboardWindow.shutdown()` を呼び、タイマー停止・`data_changed` の接続解除・ウィンドウの破棄(`deleteLater()`)・保持参照の解除を行う。`shutdown()` は冪等(2 回目以降は何もしない)で、呼び出し後は終了状態となり、表示・再集計を拒否する。復元成功後の `_request_exit` 経由の `closeEvent` と重複しても二重処理にならない。予約済み通知が残っていても Service を呼ばない |
| 表示用スナップショット・集計エラー | 最後に成功した選択条件・選択肢・集計結果を保持し、選択肢の再取得と集計の成功後に表示を更新する。`DomainError` は `run_guarded` で表示し、失敗時は条件と選択肢も最後の成功状態へ戻して表・グラフ・合計を維持する。条件復元中はシグナルを抑止する。画面状態は「未取得」「表示中」の 2 値とし、初期状態は「未取得」(合計は「--」、表・グラフは空、年度コンボは空で無効)。失敗しても状態は変えず、「未取得」なら「未取得」のまま、「表示中」なら最後の成功状態へ戻す。「未取得」では CSV 出力・PNG 保存を不活性にする。失敗時のダイアログは再集計 1 回につき 1 件とし、「古い」印は残して次の `showEvent` または条件変更で再試行する |
| 性能 | `dashboard_result` と画面の再集計+描画をそれぞれ 2 秒以内とし、品目 5,000・履歴 100,000 件の DB で内訳軸「クライアント×発注主体」の月次・年次推移を計測して 4.1 に記録する |
| 6c: PR 分割 | 1 PR(`feature/phase6-dashboard-item-category`)。`GroupBy` の廃止で core と UI が同時に変わり、`main` を常にテスト成功状態に保つため分割しない。コミットは「文書(正本・本書)→ core → UI → テスト・性能・文書同期」の順にする。6b のマージ後の最新の `main` から作成する |
| 6c: 絞り込み軸 | 既存のクライアント・発注主体に、品目(単一)とカテゴリ(単一)を加え、すべて AND で結合する。品目とカテゴリは互いに連動させない(品目がカテゴリ配下になければ結果は 0 件)。年度・期間の定義は変えない |
| 6c: カテゴリの絞り込み | 選択したカテゴリとその全子孫カテゴリに属する品目を対象にする(品目一覧の絞り込みと同じ挙動)。履歴はカテゴリを持たないため、品目の**現在の**カテゴリで過去履歴を集計する。スキーマ(`schema.sql`・`migrations.py`・`SCHEMA_VERSION`)は変更しない |
| 6c: 品目の選択 | 編集可能な `QComboBox` に `QCompleter`(部分一致・大文字小文字無視)を付けた単一選択。先頭は「すべて」、表示は「管理番号 品名」、無効化済みの品目も「(無効)」付きで含める。`QComboBox.InsertPolicy.NoInsert` を指定し、確定済みの選択 ID と編集中の文字列を区別する。候補の選択(コンボ・補完)、Enter、フォーカス移動で確定する。入力文字列が候補の表示文字列と一致するときだけその ID を採用し、ID が変わった場合に 1 回再集計する。候補にない文字列(空欄を含む)は直前の確定済み選択の表示へ戻し、候補を追加せず再集計もしない。候補は `InventoryService` に新設する軽量取得(ID・管理番号・品名・有効/無効のみ)で読み、購入情報まで計算する `list_items` は使わない |
| 6c: 内訳軸 | `GroupBy`(排他の 4 値)を廃止し、`GroupAxis`(`CLIENT`・`PURCHASER`・`CATEGORY`・`ITEM` の `StrEnum`)の `frozenset` で複数軸を自由に組み合わせる(空集合が従来の「なし」、`{CLIENT, PURCHASER}` が従来の「クライアント×発注主体」)。UI は 4 つの `QCheckBox`(既定はすべてオフ)。カテゴリ別は品目の直接カテゴリで、表示はパス表記(例: `電気 > ケーブル`)。品目別とカテゴリ別の併用も許可する。行は履歴のある組み合わせだけ(0 埋めは内訳軸なしのときだけ。現行どおり) |
| 6c: 行キーと並び | 内訳軸に含まれない軸でも、その軸で絞り込み中なら行の ID・名称に絞り込み対象を設定し、未絞り込みの軸だけ `None`(現行の「絞り込み軸の行キー」と同じ規則)。内訳行の並びは「期間 → クライアント ID → 発注主体 ID → カテゴリのパス → 品目の管理番号」。`totals` は内訳軸によらず同一 |

### 4.3 先行確認(6a・D)

(`QChartView.setChart` が旧チャートを自動削除するかの確認結果(Windows・Linux offscreen)と、採用した解放方法を記録する。)

- Windows / PySide6: `setChart(new)` 直後も旧チャートは `shiboken6.isValid(old) == True`。`deleteLater()` と `QEvent.DeferredDelete` 処理後に `False` となるため、差し替え後に有効性を確認して旧チャートを解放する。
- Linux offscreen / PySide6 6.11.2 / Qt 6.11.2: `setChart(new)` 直後も旧チャートは `shiboken6.isValid(old) == True`。`deleteLater()` と `QEvent.DeferredDelete` 処理後に `False` となることを確認した。実装は `view.chart()` で旧チャートを取得し、差し替え後に有効性を確認してから `deleteLater()` する。

## 5. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 年度境界の既存不整合を引き継ぐ | 現在年度の履歴が表示されず、年度ラベルと集計期間がずれる | B で開始年の定義に統一する。旧 API との一致だけでなく、境界直前・境界上・現在日時の履歴を独立した手計算の期待値で検証する |
| 内訳軸「クライアント×発注主体」で行数が増え、描画・集計が遅くなる | 2 秒の目標超過 | 合計と内訳を 1 回の走査で作る。表は `QAbstractTableModel` で扱い、グラフは `totals`(期間数のみ)を描画する。J で計測し、超過時は集計の Python 側の処理を見直す |
| 年次の全年度推移で、年度数が多いとグラフの棒が詰まる | 見づらい | 履歴の年数は通常数年程度とし、カテゴリ軸のラベルを間引かない。手動確認で確認し、問題があれば最大表示年度数を別途検討する |
| `data_changed` が連続発火して再集計が多重に走る | 操作の遅延 | 単発 `QTimer` で合流し、非表示中は再集計しない |
| 閉じる操作・復元の上書き・終了後に予約済みの再集計が動く | 例外・不整合な表示 | 非表示時(`hideEvent`)に予約済みタイマーを停止し、復元・終了時は冪等な `shutdown()` で終了状態への移行・通知の接続解除・破棄・保持参照の解除を行う。コールバックの状態確認と予約直後の非表示・復元・終了、`shutdown()` の二重呼び出しのテストで固定する |
| 集計失敗後に条件と表示結果が食い違う | 異なる対象の数値を確認・出力する | 条件・選択肢・結果を表示用スナップショットとして保持し、失敗時は最後の成功状態へ戻す。初回失敗時は出力を不活性にし、E・H で検証する |
| `grab()` の画像がスクロール・オフスクリーン・高 DPI で欠ける | 片方のグラフが保存されない | viewport ではなく全コンテンツを保存する。Linux offscreen のテストで devicePixelRatio を考慮した寸法・両グラフ領域の非単色・スクロール位置によらない保存を検証し、Windows の手動確認で目視する |
| PNG の保存途中の失敗で既存ファイルが壊れる | 利用者データの損失 | `QSaveFile` の `commit()` を使い、失敗時は元ファイルを保持する |
| `export_dashboard_csv` の引数変更で既存呼び出しが壊れる | テスト・性能計測の失敗 | B で呼び出し元をすべて更新し、`pyright` と全テストで確認する |
| 文字サイズ 150% でチャートと表が作業領域に収まらない | 画面の崩れ | グラフタブを `QScrollArea` に置き、チャート最小高さをフォントに比例させる。固定寸法を使わず、I で検証する |
| QChart 再生成や軸の付け替えでメモリリークや描画不整合が起きる | メモリ増加やカテゴリ軸ラベルのズレ | 方式B(新しい `QChart` を生成して `setChart` で差し替え)を採用し、古いオブジェクトの参照を残さない。`setChart` の所有権の挙動を先行確認し、`shiboken6.isValid(old)` で有効なときだけ `deleteLater()` する(二重解放による `RuntimeError` を避ける) |
| 廃棄表に実績のない組み合わせ行が大量に並ぶ | 廃棄実績の一覧性が損なわれる | 画面の廃棄表は廃棄実績のある行(廃棄数 > 0 または 廃棄額 > 0)のみをフィルタ表示する(CSV は正本どおり全行出力) |
| 6a のマージ後に正本と実装が不一致になる | 後続実装の基準が曖昧になる | A で 6a の仕様変更を実装前に正本へ反映し、同じ PR に含める。6b では出力仕様・完了状況を同期する |
| 6c: 内訳軸の全軸(クライアント×発注主体×カテゴリ×品目)で内訳行が履歴件数に近い規模になる | 集計・表示・CSV 出力が遅くなる、表が長くなる | 履歴のある組み合わせだけを行にし、表は `QAbstractTableModel`、グラフは `totals` のみ描画する(現行方針のまま)。Q で全軸の月次・年次を計測し、2 秒を超える場合は Python 側の畳み込みを見直す |
| 6c: 品目候補 5,000 件を再集計のたびに読み直す | 条件変更の応答が遅くなる | 軽量取得(ID・管理番号・品名・有効/無効のみ)にし、Q で計測する。目標を超える場合は P のとおり読み直しを `showEvent`・`data_changed` に限定する |
| 6c: 品目のカテゴリ変更で過去の集計値が変わる | 過去月の値が操作前後で食い違う | 履歴にカテゴリを持たない仕様として 2.3 と開発計画書 5.7 に明記し、テストで固定する。履歴時点のカテゴリの保持(スキーマ変更)は 2.4 のとおり対象外 |
| 6c: `GroupBy` の廃止で呼び出し元・テストの置き換え漏れが出る | 実行時エラー・テスト失敗 | N で全参照を `GroupAxis` に置き換え、`pyright`(strict の `core/`)と全テストで確認する。旧 4 値との期待値の一致を N のテストで固定する |
| 6c: 絞り込み欄の増加で 1366×768・文字サイズ 150% に収まらない | 画面の崩れ | 絞り込み欄を 2 段に分け、固定寸法を使わず、Q の表示検証と手動確認で確認する |
