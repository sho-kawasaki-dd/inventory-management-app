## 1. 目的

- クライアント・発注主体を独立に絞り込み、年度・月ごとの入庫数・出庫数・支出額(出庫基準。FIFO 原価)を、グラフと内訳表で確認できるようにする(開発計画書 5.7)。
- 内訳軸(なし / クライアント別 / 発注主体別 / クライアント×発注主体)を切り替え、廃棄数・廃棄額と単価未登録数量を別枠で確認できるようにする。
- 表示中の集計を CSV、グラフを PNG で出力できるようにする(開発計画書 5.8)。
- 品目 5,000 件・履歴 100,000 件でも、ダッシュボードの集計を 2 秒以内で表示する(開発計画書 7.5)。

## 2. 要件

### 2.1 満たすべき仕様

- 開発計画書 5.7(ダッシュボード集計)、5.8(CSV)、6.3(Dashboard)、6.4(表示要件)、7.5(性能)に従う。
- 完了条件(開発計画書 9 章): 5.7 の集計がテストデータと一致する。CSV / PNG を出力できる。
- `core/` と `db/` は PySide6 を import しない。UI は `sqlite3`・`inventory_manager_mini.db` を import せず、Service のみを呼ぶ。
- 集計値は Python の任意精度整数で計算し、5.2.1 の集計上限で検証する。SQL の `SUM` に依存せず、列名を文字列で組み立てない。
- 期間境界はローカル暦を `core/timeutil.py` で UTC に変換し、半開区間 `[start, end)` で判定する。取り消し行は元行の `moved_at` で期間判定する。
- 年度は開始年で表す。開始月を `s` とすると、年度 `y` の期間は `[y年s月1日, (y+1)年s月1日)` とする(開発計画書 5.7)。年度列挙・現在年度・月次/年次集計の定義を統一する。
- 内訳軸によらず、同一の絞り込み条件の合計は一致する。返品・棚卸(初期数量を含む)は集計に含めない。
- 無効化済みのクライアント・発注主体も、過去履歴の集計対象として選択肢に含める。
- 1366×768 で全体が作業領域に収まり、文字サイズ 150% でも同様とする(開発計画書 6.4)。
- 次のコマンドがローカル(Windows)と CI(Windows/Linux)で成功する。
  - `uv sync --locked`
  - `uv run ruff check` / `uv run ruff format --check`
  - `uv run pyright`(`core/`・`db/` は strict、`ui/` ほかは standard でエラー 0 件)
  - `uv run pytest --cov`(Linux は `QT_QPA_PLATFORM=offscreen`)
  - `uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90`
- テストで実データの保存先(`%APPDATA%` 等)を使用しない。ファイル選択ダイアログ・メッセージボックスはテストで差し替える。

| 年度の定義 | 年度は開始年で表し、開始月 `s` の年度 `y` は `[y年s月1日, (y+1)年s月1日)`。既存の前年開始の挙動は互換性維持の対象にせず、年度列挙・現在年度と一致させる |
| 年次表示 | 全年度の推移。`available_fiscal_years()` の全年度を 1 年度 1 区間で並べる。年度選択は月次のときだけ有効にする(年次では無効化) |
| 月次表示 | 選択した年度の 12 か月。既定の年度は現在の年度、既定の表示は月次、既定の内訳軸は「なし」 |
| グラフ構成 | 数量グラフ(入庫数・出庫数の棒)と金額グラフ(支出額の棒)を上下に配置する。単位が異なる指標を 1 つの軸に混在させない。縦軸は 0 始まりで、全値が 0 のときは 0〜1 とする。グラフは絞り込み結果の合計(内訳軸によらない)を表示し、内訳は表で確認する。カテゴリ軸はラベルの重なりを防ぐため斜め(-45度)に傾けて表示する。チャート更新は方式B(新しい `QChart` を生成して `setChart` で差し替え、旧チャートを確実に解放)を採用し、差分更新特有のラベル描画ズレを防ぎメモリを確実に解放する。`setChart` が旧チャートを自動削除するかは実装前に実機で確認し(D)、`deleteLater()` の二重解放を避ける。グラフタブは `QScrollArea`(`setWidgetResizable(True)`)内に 2 つの `QChartView` を縦に並べたコンテンツウィジェットを置き、各チャートの最小高さは `fontMetrics().height()` に比例させてフォントに追従させる |
| 画面構成 | 上段に絞り込み(クライアント・発注主体・年度・年次/月次・内訳軸)、合計ラベル、`QTabWidget`(「グラフ」「内訳」「廃棄」)、下段に CSV 出力・PNG 保存・閉じる。「内訳」は入庫数・出庫数・支出額・単価未登録数量、「廃棄」は廃棄数・廃棄額。画面の「廃棄」表は廃棄実績のある行(廃棄数 > 0 または 廃棄額 > 0)のみを表示し、実績のない行は除外して一覧性を保つ(CSV は 5.8 どおり全行を出力する) |
| 集計 API | `ReportService.dashboard_result()` が「期間ごとの合計(全期間を 0 で埋める)」と「内訳軸の行」を 1 回の SQL・1 回の走査で返す。内訳軸がある場合も集計を 2 回に分けない。既存の `dashboard()` は互換のため残し、内訳行を返す |
| 年次の引数 | `dashboard_result(fiscal_year=None, ANNUAL)` で全年度の推移。`fiscal_year=None` と `MONTHLY` の組み合わせは `ValueError`。年度の列挙と集計は同じ読み取りトランザクション内で行う |
| 絞り込み軸の行キー | 内訳軸に含まれない軸でも、その軸で絞り込み中なら行の ID・名称に絞り込み対象を設定する。未絞り込みの軸だけ `None`(CSV では「(すべて)」)。存在しない ID は `ValidationError` |
| ダッシュボード CSV | 画面に表示中の内訳行をそのまま出力する(再集計しない)。`export_dashboard_csv(path, rows)` とし、列は開発計画書 5.8 の 9 列。畳み込んだ軸は未絞り込みなら「(すべて)」、絞り込み中ならその名称を出力する。開発計画書 5.8 にこの規則を追記する |
| PNG | 集計取得済みかつグラフタブ表示中のみ活性。数量・金額の 2 グラフを含む全コンテンツウィジェットを `grab()` で 1 枚に保存する。スクロール対応時も viewport ではなく内部の全コンテンツを取得し、スクロール位置によらず両グラフを欠けなく保存する。`QSaveFile` に書いて `commit()` し、失敗時は既存ファイルを壊さず `FileOutputError` を発生させる |
| 保存先の選択 | `ui/csv_export.py` の保存先選択(拡張子補完・補完後の上書き確認)を拡張子・既定名・フィルタを受け取る汎用関数にし、CSV と PNG で共用する。既存 CSV の挙動は変えない |
| 再集計のタイミング | 条件変更時は即時に再集計する(待機カーソル、`run_guarded` 内)。`data_changed` は、表示中のみ `QTimer` の単発タイマー(連続発火をまとめる)で再集計し、非表示中は「古い」印だけ付けて次の `showEvent` で再集計する。`showEvent` は「古い」印があるとき(初期状態を含む)だけ再集計し、最小化からの復帰(spontaneous)では再集計しない。再集計時は年度とマスタの選択肢を読み直し、選択中の値は可能な限り維持する |
| 通常の閉じる操作 | 「閉じる」ボタン・ウィンドウの ×・`hide()` はいずれも非表示にするだけでインスタンスを保持する。非表示時の処理は `closeEvent` ではなく `hideEvent`(最小化による spontaneous なものは除く)で行い、予約済みの再集計タイマーが動いていれば停止して「古い」印を付ける。タイマーが動いていなければ印は付けず、非表示中の `data_changed` でのみ印を付ける(`hide()` → `show()` だけでは再集計しない)。再集計コールバックは非表示中または終了状態なら Service を呼ばない |
| 復元・終了との関係 | 復元の上書きを始める前と MainWindow の新設 `closeEvent` で `DashboardWindow.shutdown()` を呼び、タイマー停止・`data_changed` の接続解除・ウィンドウの破棄(`deleteLater()`)・保持参照の解除を行う。`shutdown()` は冪等(2 回目以降は何もしない)で、呼び出し後は終了状態となり、表示・再集計を拒否する。復元成功後の `_request_exit` 経由の `closeEvent` と重複しても二重処理にならない。予約済み通知が残っていても Service を呼ばない |
| 表示用スナップショット・集計エラー | 最後に成功した選択条件・選択肢・集計結果を保持し、選択肢の再取得と集計の成功後に表示を更新する。`DomainError` は `run_guarded` で表示し、失敗時は条件と選択肢も最後の成功状態へ戻して表・グラフ・合計を維持する。条件復元中はシグナルを抑止する。画面状態は「未取得」「表示中」の 2 値とし、初期状態は「未取得」(合計は「--」、表・グラフは空、年度コンボは空で無効)。失敗しても状態は変えず、「未取得」なら「未取得」のまま、「表示中」なら最後の成功状態へ戻す。「未取得」では CSV 出力・PNG 保存を不活性にする。失敗時のダイアログは再集計 1 回につき 1 件とし、「古い」印は残して次の `showEvent` または条件変更で再試行する |
| 性能 | `dashboard_result` と画面の再集計+描画をそれぞれ 2 秒以内とし、品目 5,000・履歴 100,000 件の DB で内訳軸「クライアント×発注主体」の月次・年次推移を計測して 4.1 に記録する |
