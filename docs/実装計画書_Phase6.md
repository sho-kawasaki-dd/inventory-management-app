## 1. 目的

- クライアント・発注主体を独立に絞り込み、年度・月ごとの入庫数・出庫数・支出額(出庫基準。FIFO 原価)を、グラフと内訳表で確認できるようにする(開発計画書 5.7)。
- 内訳軸(なし / クライアント別 / 発注主体別 / クライアント×発注主体)を切り替え、廃棄数・廃棄額と単価未登録数量を別枠で確認できるようにする。
- 表示中の集計を CSV、グラフを PNG で出力できるようにする(開発計画書 5.8)。
- 品目 5,000 件・履歴 100,000 件でも、ダッシュボードの集計を 2 秒以内で表示する(開発計画書 7.5)。

## 2. 要件

### 2.1 満たすべき仕様

- 開発計画書 5.7(ダッシュボード集計)、5.8(CSV)、6.3(Dashboard)、6.4(表示要件)、7.5(性能)に従う。
- 完了条件(開発計画書 9 章): 5.7 の集計がテストデータと一致する。CSV / PNG を出力できる。
- `core/` と `db/` は PySide6 を import しない。UI は `sqlite3`・`inventory_manager_mini.db` を import せず、Service のみを呼ぶ。
- 集計値は Python の任意精度整数で計算し、5.2.1 の集計上限で検証する。SQL の `SUM` に依存せず、列名を文字列で組み立てない。
- 期間境界はローカル暦を `core/timeutil.py` で UTC に変換し、半開区間 `[start, end)` で判定する。取り消し行は元行の `moved_at` で期間判定する。
- 内訳軸によらず、同一の絞り込み条件の合計は一致する。返品・棚卸(初期数量を含む)は集計に含めない。
- 無効化済みのクライアント・発注主体も、過去履歴の集計対象として選択肢に含める。
- 1366×768 で全体が作業領域に収まり、文字サイズ 150% でも同様とする(開発計画書 6.4)。
- 次のコマンドがローカル(Windows)と CI(Windows/Linux)で成功する。
  - `uv sync --locked`
  - `uv run ruff check` / `uv run ruff format --check`
  - `uv run pyright`(`core/`・`db/` は strict、`ui/` ほかは standard でエラー 0 件)
  - `uv run pytest --cov`(Linux は `QT_QPA_PLATFORM=offscreen`)
  - `uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90`
- テストで実データの保存先(`%APPDATA%` 等)を使用しない。ファイル選択ダイアログ・メッセージボックスはテストで差し替える。

| マスタ取得 | `MasterService.list_clients` / `list_purchasers(include_inactive=True)` で無効化済みを含めて取得できる |

| 画面 | 「表示」メニューにダッシュボードなし。`ui/widgets/dashboard.py`・`ui/models/dashboard_table_model.py` は未作成 |
| チャート | `QtCharts` は `tests/test_qt_smoke.py` で描画と `grab()` を検証済み。製品コードでは未使用 |
| 共通部品 | CSV の保存先選択・拡張子補完・上書き確認は `ui/csv_export.py`、エラー表示は `ui/error_handling.run_guarded`、画面サイズ検査は `tests/conftest.py` の `assert_fits_work_area` / `assert_buttons_reachable` |
| 性能テスト | `tests/test_performance.py` に年次・月次の `dashboard()` 計測(2 秒)が既にある。内訳軸付き・画面描画込みの計測はない |

### 2.3 決定事項

| 項目 | 決定 |
| --- | --- |
| PR 分割 | 6a(文書・core の補強・ダッシュボード画面)→ 6b(CSV・PNG 出力・150% / 性能検証・文書同期)の 2 PR。各 PR は CI 成功後にマージし、後続は直前のマージ後の最新の `main` から作成する |
| 画面形式 | 非モーダルの独立ウィンドウ(`Qt.Window`、親は MainWindow)。「表示」メニューの「ダッシュボード」から開き、インスタンスは 1 つだけ保持する。2 回目以降は既存のウィンドウを前面に出す。ツールバーには追加しない(開発計画書 6.2 に記載がないため) |
| 年次表示 | 全年度の推移。`available_fiscal_years()` の全年度を 1 年度 1 区間で並べる。年度選択は月次のときだけ有効にする(年次では無効化) |
| 月次表示 | 選択した年度の 12 か月。既定の年度は現在の年度、既定の表示は月次、既定の内訳軸は「なし」 |
| グラフ構成 | 数量グラフ(入庫数・出庫数の棒)と金額グラフ(支出額の棒)を上下に配置する。単位が異なる指標を 1 つの軸に混在させない。縦軸は 0 始まりで、全値が 0 のときは 0〜1 とする。グラフは絞り込み結果の合計(内訳軸によらない)を表示し、内訳は表で確認する |
| 画面構成 | 上段に絞り込み(クライアント・発注主体・年度・年次/月次・内訳軸)、合計ラベル、`QTabWidget`(「グラフ」「内訳」「廃棄」)、下段に CSV 出力・PNG 保存・閉じる。「内訳」は入庫数・出庫数・支出額・単価未登録数量、「廃棄」は廃棄数・廃棄額 |
| 集計 API | `ReportService.dashboard_result()` が「期間ごとの合計(全期間を 0 で埋める)」と「内訳軸の行」を 1 回の SQL・1 回の走査で返す。内訳軸がある場合も集計を 2 回に分けない。既存の `dashboard()` は互換のため残し、内訳行を返す |
| 年次の引数 | `dashboard_result(fiscal_year=None, ANNUAL)` で全年度の推移。`fiscal_year=None` と `MONTHLY` の組み合わせは `ValueError`。年度の列挙と集計は同じ読み取りトランザクション内で行う |
| 絞り込み軸の行キー | 内訳軸に含まれない軸でも、その軸で絞り込み中なら行の ID・名称に絞り込み対象を設定する。未絞り込みの軸だけ `None`(CSV では「(すべて)」)。存在しない ID は `ValidationError` |
| ダッシュボード CSV | 画面に表示中の内訳行をそのまま出力する(再集計しない)。`export_dashboard_csv(path, rows)` とし、列は開発計画書 5.8 の 9 列。畳み込んだ軸は未絞り込みなら「(すべて)」、絞り込み中ならその名称を出力する。開発計画書 5.8 にこの規則を追記する |
| PNG | グラフタブ表示中のみ活性。数量・金額の 2 グラフを含む領域を `grab()` で 1 枚に保存する。`QSaveFile` に書いて `commit()` し、失敗時は既存ファイルを壊さず `FileOutputError` を発生させる |
| 保存先の選択 | `ui/csv_export.py` の保存先選択(拡張子補完・補完後の上書き確認)を拡張子・既定名・フィルタを受け取る汎用関数にし、CSV と PNG で共用する。既存 CSV の挙動は変えない |
| 再集計のタイミング | 条件変更時は即時に再集計する(待機カーソル、`run_guarded` 内)。`data_changed` は、表示中のみ `QTimer` の単発タイマー(連続発火をまとめる)で再集計し、非表示中は「古い」印だけ付けて次の `showEvent` で再集計する。再集計時は年度とマスタの選択肢を読み直し、選択中の値は可能な限り維持する |
| 復元・終了との関係 | 復元の上書きを始める前と MainWindow の `closeEvent` でダッシュボードを閉じる(Service の接続が差し替わる・閉じるため) |
| 集計エラー | 集計上限超過などの `DomainError` は `run_guarded` で表示し、ウィンドウは継続する(直前の表示を維持する) |
| 性能 | `dashboard_result` と画面の再集計+描画をそれぞれ 2 秒以内とし、品目 5,000・履歴 100,000 件の DB で内訳軸「クライアント×発注主体」の月次・年次推移を計測して 4.1 に記録する |

### 2.4 対象外

- 集計の非同期化・進捗表示・キャンセル
- ツールバーへのダッシュボード追加
- 日次集計、任意期間の指定、品目別・カテゴリ別の集計
- 印刷(Phase 7)、パッケージング(Phase 8)
- PNG 以外の画像形式、グラフ単体の個別保存

## 5. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 内訳軸「クライアント×発注主体」で行数が増え、描画・集計が遅くなる | 2 秒の目標超過 | 合計と内訳を 1 回の走査で作る。表は `QAbstractTableModel` で扱い、グラフは `totals`(期間数のみ)を描画する。J で計測し、超過時は集計の Python 側の処理を見直す |
| 年次の全年度推移で、年度数が多いとグラフの棒が詰まる | 見づらい | 履歴の年数は通常数年程度とし、カテゴリ軸のラベルを間引かない。手動確認で確認し、問題があれば最大表示年度数を別途検討する |
| `data_changed` が連続発火して再集計が多重に走る | 操作の遅延 | 単発 `QTimer` で合流し、非表示中は再集計しない |
| 復元の上書き・終了中にダッシュボードが古い接続で集計を行う | 例外・不整合な表示 | 復元の開始前と終了時にダッシュボードを閉じ、テストで固定する |
| `grab()` の画像がオフスクリーン・高 DPI で崩れる | PNG の欠け | Linux offscreen のテストで寸法・非単色を検証し、Windows の手動確認で目視する |
| PNG の保存途中の失敗で既存ファイルが壊れる | 利用者データの損失 | `QSaveFile` の `commit()` を使い、失敗時は元ファイルを保持する |
| `export_dashboard_csv` の引数変更で既存呼び出しが壊れる | テスト・性能計測の失敗 | B で呼び出し元をすべて更新し、`pyright` と全テストで確認する |
| 文字サイズ 150% でチャートと表が作業領域に収まらない | 画面の崩れ | 固定寸法を使わず `sizeHint` とスクロールに任せ、I で検証する |
