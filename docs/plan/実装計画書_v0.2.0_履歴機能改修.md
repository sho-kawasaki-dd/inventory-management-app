## 1. 目的

- 品目ごとの履歴ダイアログ(`HistoryDialog`)において、履歴件数が増加した際の一覧性・操作性を確保するため、1 ページあたり 300 件または 500 件(画面上で切替可能、既定 300 件)のページネーション機能を導入する。
- 品目ごとの履歴ダイアログにおいて、期間区分「全期間」「年次(選択した 1 年度分)」「月次(選択した 1 か月分)」による絞り込みを可能とし、同ダイアログからの CSV 出力内容も選択中の期間条件に追従させる。
- 全品目の履歴 CSV 出力において、専用ダイアログ(`HistoryExportDialog`)を設けてクライアント(履歴記録時点のクライアント、無効化済みを含む)および期間区分(全期間・年次・月次)による絞り込み出力を可能にする。
- 上記の機能追加に伴い、アプリケーションの版数を `0.1.0` から `0.2.0` へ引き上げ、確定した仕様を開発計画書(正本)へ統合する。

## 2. 要件

### 2.1 満たすべき仕様

- 開発計画書 3.1(層構成と依存方向)、3.4(DB 接続・日時表現)、5.3(取り消し)、5.8(CSV エクスポート)、5.9(設定: `fiscal_year_start_month`)、6.2(メニュー・ツールバー)、6.3(画面詳細)、6.4(表示要件)、7.4(セキュリティ)、8 章(テスト方針)に従う。
- `core/` と `db/` は `PySide6` を絶対に import しない。UI は `sqlite3` や `inventory_manager_mini.db` を直接扱わず、Service(`InventoryService`・`ReportService`・`MasterService`・`SettingsService`)のみを経由する。
- `core/models.py` および `core/errors.py` は `db/`・Service・UI に依存させない。
- 日時は DB には `'YYYY-MM-DD HH:MM:SS'` 形式の UTC 文字列で保存し、期間境界の計算は `core/timeutil.py` の `local_range_to_utc(start, end, tz)` を用いてローカル暦の半開区間 `[start, end)` を UTC 文字列の組 `[start_utc, end_utc)` に変換して行う。SQL 側で `'localtime'` 等のタイムゾーン補正を行わない。
- SQL はすべてプレースホルダでパラメータ化し、f-string 等で値を埋め込まない。
- 最小解像度 1366×768 かつ文字サイズ 100%・150% のいずれでも、改修後の `HistoryDialog` および新設する `HistoryExportDialog` のウィンドウ枠全体が対象画面の `availableGeometry()` 内に収まり、すべての操作欄・ボタンに到達可能であること。
- 次のコマンドがローカル(Windows)と CI(Windows/Linux)で成功すること。
  - `uv sync --locked`
  - `uv run ruff check` / `uv run ruff format --check`
  - `uv run pyright`(`core/`・`db/` は strict、`ui/` は standard でエラー 0 件)
  - `uv run pytest --cov`(Linux は `QT_QPA_PLATFORM=offscreen`)
  - `uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90`
  - `uv run python scripts/check_release_version.py --version 0.2.0`
- テストで実データの保存先(`%APPDATA%` 等)を使用しない。ファイル選択ダイアログ・メッセージボックスはテストで差し替える。

### 2.3 決定事項

| 項目 | 決定 |
| --- | --- |
| アプリ版数・スキーマ版数 | アプリ版数を `0.2.0` に引き上げる(`pyproject.toml`・`uv.lock`・`README.md`)。DB スキーマ変更は不要のため、`SCHEMA_VERSION = 4` は維持する |
| ページネーションの件数仕様 | `HistoryDialog` に表示件数コンボボックス(`300件` / `500件`、初期値 `300件`)を設ける。許可するページサイズは `HISTORY_PAGE_SIZES = (300, 500)` とし、それ以外の値は `ValueError` で拒否する |
| ページネーションの操作・表示 | 「前へ」ボタン、ページ・総件数ラベル(例: `1 / 3 ページ (全 650 件)`、該当 0 件時は `0 / 0 ページ (全 0 件)`)、「次へ」ボタン、表示件数コンボを配置する。先頭ページ(または 0 件)では「前へ」を不活性、最終ページ(または 0 件)では「次へ」を不活性とする。期間条件・表示件数を変更した際は 1 ページ目へ戻す |
| 取り消し後のページ維持・行再選択 | `HistoryDialog` で履歴の取り消しに成功した際は、現在の期間条件・表示件数のまま、取り消した元の履歴行(`movement.id`)が含まれるページを特定して表示し、元の行を選択・スクロール表示する |
| 期間区分の定義(`HistoryPeriodKind`) | `ALL`(全期間、初期値)、`ANNUAL`(年次: 選択した 1 年度分)、`MONTHLY`(月次: 選択した年度内の 1 か月分)の 3 種類とする。ダッシュボード用の `PeriodKind`(`ANNUAL`/`MONTHLY`)には「全期間」がなく集計の意味も異なるため、別の列挙型として定義する |
| 期間条件の受け渡し | 期間条件は `HistoryPeriod(kind, fiscal_year, month)` で受け渡す(`HistoryFilter` は設けない)。`ReportService.list_history_page`・`export_history_csv` は `period` 引数で受け取り、既存の `export_history_csv(path)`・`export_history_csv(path, item_id)` の呼び出しは変更なしで動作させる。クライアントは `client_id` 引数で別に渡す |
| 存在しない品目 ID | `item_id` は正の整数であることだけを検証し、存在しない ID は該当 0 件として扱う(`client_id` と異なり存在確認は行わない)。`HistoryDialog` は品目が見つからない場合の専用表示を維持し、エラーダイアログを重ねて出さない |
| ページ数の定義 | `total_pages = ceil(total_count / page_size)`(0 件のときは 0)とする。`page` は `1〜max(total_pages, 1)` にクランプし、0 件のときは `page=1, total_pages=0` を返す。`0 / 0 ページ (全 0 件)` の表示は UI 側で `total_count == 0` を判定して行う |
| 年度・月の基準 | 設定の年度開始月(`fiscal_year_start_month`、1〜12、既定 4)に従う。開始月 `s` に対し、年度 `y` の「年次」はローカル日付 `[y年s月1日, (y+1)年s月1日)` の 1 年度分とする。「月次」は選択年度 `y` に属する 12 か月(開始月 `s` から順に並ぶ各月。`m >= s` なら `y年m月`、`m < s` なら `(y+1)年m月`)のうち選択した 1 か月分 `[該当月初日, 翌月初日)` とする |
| 年度・月コンボの選択肢と活性制御 | 年度コンボは `ReportService.available_fiscal_years()` の一覧(`"{year}年度"`、初期選択は `current_fiscal_year()`)を表示し、`ANNUAL` または `MONTHLY` のとき活性(`ALL` では不活性)とする。月コンボは年度開始月順に 12 か月(表示ラベルは `"{actual_year}年{month}月"`、データは月番号 `1〜12`、初期選択は現在日付の月)を表示し、`MONTHLY` のときのみ活性(`ALL`・`ANNUAL` では不活性)とする。選択年度を変更した際は月コンボの表示年表記を選択年度に合わせて更新し、選択中の月番号(`1〜12`)を維持する |
| 期間判定の日時基準 | 取り消し行は元の行との対応が重要なため、取り消し以外の行は自身の `stock_movements.moved_at`、取り消し行(`reversal_of IS NOT NULL`)は元の行の `moved_at` を判定日時とする(`COALESCE(o.moved_at, m.moved_at)`、`o` は `LEFT JOIN stock_movements o ON o.id = m.reversal_of`)。`local_range_to_utc(start_date, end_date, tz)` で変換した UTC 半開区間 `[start_utc, end_utc)` で絞り込む。取り消しを実行した日時は、従来どおり「日時」列(取り消し行自身の `moved_at`)で確認する。このため、絞り込み期間外の日時を表示する取り消し行が含まれることがある。取り消しは 1 段階のみなので、元の行を 1 回たどれば足りる |
| 期間内の並び順 | 絞り込み後の並び順は判定日時ではなく、「日時」列(`m.moved_at`)の順とする。元の行との対応は「取り消し元ID」列で示す |
| 履歴の並び順 | 画面表示(`HistoryDialog`)は従来どおり新しい順(`moved_at DESC, id DESC`)、CSV 出力(品目別・全品目とも)は従来どおり古い順(`moved_at ASC, id ASC`)を維持する |
| 品目別履歴 CSV 出力 | `HistoryDialog` の「CSV 出力」ボタンは、同ダイアログで現在選択中の期間条件(全期間・年次・月次)に一致する当該品目の全履歴(ページネーションの 1 ページ分ではなく、条件一致の全件)を出力する |
| 全品目履歴 CSV 出力の UI | MainWindow の「ファイル → CSV 出力 → 履歴(全品目)」およびツールバーの「CSV 出力 → 履歴(全品目)」(同一の `export_history_action`。項目名は変更しない)実行時に、モーダルダイアログ `HistoryExportDialog` を表示する。ダイアログでクライアントと期間条件を指定して OK を押下した後に、ファイル保存ダイアログ(`export_csv_with_dialog`)を開く。キャンセル時はファイル保存ダイアログを開かず終了する |
| 全品目履歴 CSV のクライアント条件 | 「すべて」(`None`、初期選択)と `MasterService.list_clients(include_inactive=True)` の全クライアント(無効化済みは `"{name} (無効)"` 表示)を選択肢とし、履歴記録時点の `stock_movements.client_id` で絞り込む |

### 2.4 対象外

- 全品目横断の履歴閲覧画面(全品目対象は従来どおり CSV 出力のみ)
- 任意の日付範囲(カレンダーによる開始日・終了日指定)での履歴絞り込み
- 履歴ダイアログにおける列ソートや、発注主体・担当者・操作種別による絞り込み
- ダッシュボード集計ロジックの変更(ダッシュボードの年次=全年度推移、取り消し行の元行日時による相殺ルールは現行のままとする。履歴画面・CSV の期間判定もこれと同じく元行の日時基準に揃える)
- DB スキーマ・マイグレーションの変更
