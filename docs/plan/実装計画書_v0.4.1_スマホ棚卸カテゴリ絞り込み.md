# v0.4.1 実装計画書(スマホ棚卸の品目カテゴリによる対象絞り込み)

- 作成日: 2026-11-01
- ステータス: 計画中
- 作業ブランチ: `feature/v0.4.1-plan`(計画書作成)→ `feature/v0.4.1-stocktake-category`(実装・正本統合)
- 基盤とする文書: [ローカル在庫管理アプリ開発計画書](ローカル在庫管理アプリ開発計画書.md)(3.1・3.2・4.1・4.2・4.4・5.2.3・5.4・6.3・7.2・8 章)
- 利用者確認: ロックはクライアント単位を維持、カテゴリは単一選択(子孫を含む)、対象品目 ID をスナップショットして照合(2026-11-01)

---

## 1. 目的

- スマホ棚卸の対象を「クライアントの有効品目すべて」だけでなく、「クライアント × 品目カテゴリ(子孫カテゴリを含む)」で絞り込めるようにし、保管場所や担当範囲ごとに少ない品目数で棚卸を行えるようにする。
- 棚卸中にカテゴリの階層が変わっても、シート出力時に確定した対象品目で正しく取り込み・確定できるようにする。
- 上記の改修に伴い、アプリの版数を `0.4.0` から `0.4.1` へ、スキーマ版数を `5` から `6` へ引き上げ、確定した仕様を開発計画書(正本)へ統合する。

### 2.2 既存実装の状況(調査結果)

| 項目 | 状況 |
| --- | --- |
| ロック | `active_stocktakes`(主キー `client_id`)でクライアント単位に 1 セッションを保持。`InventoryService._require_client_not_in_stocktake()` が品目の現在の `client_id` で禁止操作を判定する |
| 対象品目の決定 | `InventoryService._begin_mobile_stocktake()` が `items.list(ItemFilter(client_id=...))` で対象クライアントの有効品目すべてを取得する |
| 取り込み時の照合 | `_validate_mobile_stocktake_payload()` が「現在の対象クライアントの有効品目」の ID 集合と結果の品目 ID 集合の完全一致を検査する(対象品目は保存していない) |
| 品目数の表示 | `StocktakeRepository._SELECT` の `item_count` は、対象クライアントの現在の有効品目数を副問い合わせで算出している |
| カテゴリ | `categories` は `parent_id` による階層構造。論理削除はなく、未使用なら物理削除できる(`MasterRepository.category_in_use()`)。名称変更・親の変更(`move_category`)はロック中でも許可されている。`ItemFilter.category_id` は子孫カテゴリを含めて絞り込む。品目の `category_id` は NOT NULL |
| カテゴリ選択 UI | `ui/widgets/category_picker.py` の `CategoryPicker`(木構造から 1 件選択、`leading_label` で「すべて」相当の先頭項目を表示可能)がメイン画面・品目ダイアログ・ダッシュボードで使われている |
| 結果形式 | 結果テキスト・結果 JSON(`PAYLOAD_VERSION = 1`)は `session_id`・`client_id`・`entries` のみを持つ。HTML 側の途中保存(IndexedDB/途中バックアップ v1)は、シートに埋め込んだ品目一覧との一致を検証する |
| スキーマ版数 | `SCHEMA_VERSION = 5`(`schema.sql` が最新版、`schema_v3.sql`・`schema_v4.sql` が固定版)。`scripts/check_bundle.py` は `schema_v4.sql` の同梱を検査している |
| 版数定義 | `pyproject.toml` の `version = "0.4.0"`。`uv.lock`・`README.md`・`tests/test_app.py`・`tests/test_main_window.py` に `0.4.0` が記載されている |

### 2.3 決定事項

| 項目 | 決定 |
| --- | --- |
| ロック単位 | 従来どおりクライアント単位で同時に 1 件とする。カテゴリを絞り込んだ場合も、ロック中の禁止操作は対象クライアントの全品目に適用する(5.2.3 の禁止操作・許可操作は変更しない) |
| カテゴリ選択 | 単一選択とし、選択したカテゴリとその子孫カテゴリに属する有効品目を対象とする。未選択(「すべてのカテゴリ」)は従来どおりクライアントの有効品目すべてを対象とする |
| 対象品目の確定 | シート出力時に対象品目 ID を新テーブル `active_stocktake_items` にスナップショットし、取り込み・確定はスナップショットと照合する。カテゴリ階層の変更(名称変更・移動)では対象品目は変わらない |
| スキーマ v6 | `active_stocktakes` に `category_id INTEGER REFERENCES categories(id)`(NULL = すべてのカテゴリ)を追加し、`active_stocktake_items` を追加する(下記 DDL) |
| v5 からの移行 | 進行中の各セッションについて、移行時点の対象クライアントの有効品目すべてをスナップショットに登録し、`category_id` は NULL とする(従来の「全有効品目」と同じ対象を維持し、移行前に作成したシートの結果をそのまま取り込めるようにする) |
| 照合の規則 | 結果の品目 ID 集合がスナップショットと完全一致し、かつスナップショットの全品目が「有効」かつ「現在の `client_id` が対象クライアント」であることを検査する。不一致は `ValidationError` で拒否する(ロックにより通常は発生しない。復元等の異常時の防衛線) |
| 結果形式 | 結果テキスト・結果 JSON・途中保存形式(IndexedDB v1・途中バックアップ v1)は変更しない(`PAYLOAD_VERSION = 1` を維持)。対象範囲はセッションで特定する |
| 表示 | シート HTML の見出し・`<title>`、PC 側の手続き中一覧、結果プレビュー、確定・中止・再作成の確認表示に対象カテゴリ(フルパス、未選択時は「すべてのカテゴリ」)を表示する。カテゴリ名は表示時点の名称・階層を使う。メイン画面のロックバナーはクライアント単位のロック表示のままとし変更しない |
| ファイル名 | PC 側の推奨シートファイル名は、カテゴリ選択時に `棚卸シート_<クライアント>_<カテゴリ名(末端)>_<日時>_<乱数>.html` とする(未選択時は従来どおり)。HTML 側の結果・途中バックアップのファイル名は変更しない |
| カテゴリの物理削除 | 進行中セッションの `category_id` から参照されるカテゴリは使用中として削除を拒否する(`category_in_use()` に条件を追加し、FK を最終防衛線とする) |
| 品目数 | `ActiveStocktake.item_count` はスナップショット件数とする |
| 版数 | アプリ版数を `0.4.1`、スキーマ版数を `6` とする。v0.4.1 の DB・バックアップは v0.4.0 以前のアプリでは `SchemaTooNewError` となる |

v6 で追加・変更する DDL(`db/schema.sql`):

```sql
CREATE TABLE active_stocktakes (
  client_id INTEGER PRIMARY KEY REFERENCES clients(id),
  session_id TEXT NOT NULL UNIQUE CHECK (
    typeof(session_id) = 'text'
    AND length(session_id) = 32
    AND session_id NOT GLOB '*[^0-9a-f]*'
  ),
  staff_id INTEGER NOT NULL REFERENCES staff(id),
  started_at TEXT NOT NULL DEFAULT (datetime('now')),
  category_id INTEGER REFERENCES categories(id)
);

CREATE TABLE active_stocktake_items (
  client_id INTEGER NOT NULL REFERENCES active_stocktakes(client_id) ON DELETE CASCADE,
  item_id INTEGER NOT NULL REFERENCES items(id),
  PRIMARY KEY (client_id, item_id)
);
```

### 2.4 対象外

- 対象品目だけをロックし、同一クライアントで複数の棚卸を並行させること。
- 複数カテゴリの同時選択、保管場所など他の条件による絞り込み。
- 結果形式・途中保存形式の版数変更、既に作成・配布済みの HTML の更新・移行。
- メイン画面のロックバナー・品目ダイアログ・在庫操作ダイアログのロック判定の変更。
