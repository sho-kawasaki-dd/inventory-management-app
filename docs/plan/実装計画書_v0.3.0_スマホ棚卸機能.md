## 1. 目的

- 事務所 PC のネットワーク外にある各クライアント現場へ Android スマートフォンを持ち出し、ブラウザ上のボタン操作(ポチポチ入力)で月次棚卸を完結させ、帰社後に事務所 PC へ安全に一括反映できるようにする。
- アプリケーションのオフライン原則(ブラウザ起動以外の外部通信・ポート待受を行わない)を維持するため、対象クライアントの品目データと操作 UI(CSS/JavaScript)を単一ファイルに内包した**自己完結型 HTML シート**を出力し、帰社後は**結果テキスト(`IMM1:<Base64>`)のコピー＆貼り付け**または**結果ファイル(`.json`)の読込**の 2 経路で取り込めるようにする。
- 棚卸シート出力中(棚卸手続き中)の在庫変動や品目構成の食い違いによる不整合を確実に防ぐため、DB スキーマを `v5`(`active_stocktakes` テーブル追加)へ引き上げ、**棚卸手続き中の対象クライアントに関わる在庫操作・品目追加/編集/廃止・マスタ無効化/削除を全面禁止する厳格ロック(方式①)**を導入する。
- 出発前の「棚卸シート出力・ロック管理」と帰社後の「結果取り込み・差分プレビュー・一括確定」を 1 つの専用ダイアログ(`MobileStocktakeDialog`)およびメイン画面上部の通知バナーに集約し、操作者が迷わない導線を提供する。
- 上記の機能追加に伴い、アプリケーションの版数を `0.2.0` から `0.3.0` へ、DB スキーマ版数を `4` から `5` へ引き上げ、確定した仕様を開発計画書(正本)へ統合する。

### 2.2 既存実装の状況(調査結果)

| 項目 | 状況 |
| --- | --- |
| スキーマ・マイグレーション | 現行は `SCHEMA_VERSION = 4`、`MIN_SUPPORTED_SCHEMA_VERSION = 1`。`db/schema.sql` が最新版(v4)であり、v3 は `db/schema_v3.sql` として固定保存されている。`scripts/check_bundle.py` と `tests/test_check_bundle.py` が `db/schema.sql` と `db/schema_v3.sql` の同梱を検査している |
| 個別棚卸(`InventoryService.stocktake`) | 単一品目に対し `actual_quantity`(`0〜MAX_STOCK_QUANTITY`)を受け取り、`delta = actual - item.quantity` で `Reason.ADJUST` 履歴を記録する。`delta == 0` でも記録し、`delta > 0` は `item.reference_price` をロット単価とし、`delta < 0` は `plan_fifo_allocations` で FIFO 引当を行う |
| 集計管理テーブル(`total_aggregates`) | `Reason.ADJUST` は入庫数・出庫数・廃棄数・支出額・廃棄額のいずれにも計上しないため(`_aggregate_deltas` が空辞書を返す)、一括棚卸でも `total_aggregates` の値は変化しない(減少時の `stock_allocations` のみ追加される) |
| マスタ使用中判定(`MasterRepository`) | `client_in_use` は `items` と `stock_movements`、`staff_in_use` は `stock_movements` の参照有無を検査している |
| 依存ルール検査(`tests/test_dependency_rules.py`) | `core/`・`db/` の `PySide6` 非依存、`db/` から Service/UI への import 禁止、`core/models.py`・`core/errors.py` の独立性、`core/timeutil.py` 以外での `datetime.now` / `'localtime'` 禁止を AST で自動検査している |

### 2.3 決定事項

| 項目 | 決定 |
| --- | --- |
| アプリ版数・スキーマ版数 | アプリ版数を `0.3.0` に引き上げる(`pyproject.toml`・`uv.lock`・`README.md`)。DB スキーマ版数を `SCHEMA_VERSION = 5` に引き上げ、現行の v4 DDL を `db/schema_v4.sql` として固定保存する(`scripts/check_bundle.py` の必須ファイルにも追加) |
| 棚卸管理テーブル(`active_stocktakes`) | `client_id INTEGER PRIMARY KEY REFERENCES clients(id)`、`session_id TEXT NOT NULL UNIQUE CHECK (length(session_id) = 32 AND session_id NOT GLOB '*[^0-9a-f]*')`、`staff_id INTEGER NOT NULL REFERENCES staff(id)`、`started_at TEXT NOT NULL DEFAULT (datetime('now'))` を持つテーブルを追加する。主キーを `client_id` とすることで、クライアント単位で独立して複数同時に棚卸手続きを進められる |
| 開始条件と再出力 | 有効なクライアントかつ有効な担当者を選択して開始する。対象クライアントの有効品目(`is_active = 1`)が 0 件の場合は `ValidationError("対象クライアントに有効な品目がありません")` として開始不可とする。すでに棚卸手続き中のクライアントに対して再度シート出力を実行した場合は、新しい `session_id` と開始時刻で `active_stocktakes` を更新(再発行)し、旧シートの結果はセッション不一致として拒否する |
| 厳格ロックの禁止範囲(`StocktakeInProgressError`) | 対象クライアントが `active_stocktakes` に存在する間、以下の操作をすべて `StocktakeInProgressError` で拒否する。<br>1. 当該クライアントへの新規品目登録(`create_item`)<br>2. 当該クライアントに属する品目の属性編集(`update_item`)、および別クライアントの品目を当該クライアントへ変更する編集<br>3. 当該クライアントに属する品目の廃止(`deactivate_item`)・再有効化(`reactivate_item`)<br>4. 当該クライアントに属する品目の全在庫操作(`receive`、`issue`、`return_to_supplier`、`dispose`、`stocktake`)<br>5. 当該クライアントに属する品目の履歴取り消し(`reverse`、および `reversal_block_reason` での理由返却)<br>6. 当該クライアント自身の無効化(`deactivate_client`)・物理削除(`delete_client`)、および `active_stocktakes.staff_id` として記録されている担当者の無効化(`deactivate_staff`)・物理削除(`delete_staff`) |
| ロック中に許可する操作 | 別クライアントの品目に対する全操作、当該クライアント名・担当者名の名称変更、全クライアントの閲覧・検索・CSV 出力・印刷・ダッシュボード集計・バックアップは通常どおり許可する |
| ロック解除(棚卸中止) | `InventoryService.cancel_mobile_stocktake(client_id)` により、いつでも `active_stocktakes` から対象クライアントのレコードを削除してロックを解除できる |
| スマホ側の未確認品目の扱い | スマホ上の HTML シートでは、**全品目を「確認済」にしないと完了出力(結果テキストのコピー・結果ファイルの保存)を実行できない**仕様とする。PC 側の取り込み時(`preview_mobile_stocktake` / `complete_mobile_stocktake`)にも、対象クライアントの全有効品目が過不足なく含まれていることを検証し、不一致があれば拒否する |
| HTML シートの機能・UX | ・外部 CDN やネットワーク通信を一切使わない単一 `.html` ファイル(インライン CSS/JS + JSON データ)として生成する。<br>・Android の簡易 HTML ビューア(JS 無効環境)で開かれた際に、「右上のメニューから Chrome で開いてください」と大きく表示する `<noscript>` ガードを設ける。<br>・上部固定ヘッダに進捗バー(`確認済 X / Y 件`)、状態タブ(`未確認` / `確認済` / `差異あり` / `すべて`)、保管場所フィルタ、キーワード検索(管理番号・品名・メーカー型番)を設ける。<br>・品目カードには `✓ 帳簿通り (N 個) で OK` のワンタップ確認ボタンと、`-10` / `-1` / `実数直接入力` / `+1` / `+10` の調整ボタン、任意の備考メモ入力欄を設ける。<br>・操作ごとにブラウザの `localStorage`(キー: `imm_stocktake_<session_id>`)へ自動保存し、画面を閉じても再開可能とする。 |
| スマホから PC への戻し方 | 以下の 2 通りを両方提供する。<br>1. **結果テキスト(`IMM1:<Base64>`)**: JSON ペイロードを UTF-8 → Base64 エンコードし `IMM1:` 接頭辞を付けた文字列をクリップボードへコピー(メール本文等に貼り付けて送信可能)。PC 側は前後の余白・改行・メール引用符等が含まれるテキストからでも `IMM1:[A-Za-z0-9+/=]+` を抽出して解析できるようにする。<br>2. **結果ファイル(`.json`)**: 同じ JSON ペイロードを `棚卸結果_<クライアント名>_<日時>.json` としてスマホに保存し、PC 側のファイル選択ダイアログで読み込む。 |
| PC 側の取り込み・一括確定 | ・`preview_mobile_stocktake(raw_text)` でフォーマット・`session_id` の一致・全有効品目の網羅・数量上限(`0〜MAX_STOCK_QUANTITY`)を検証し、品目ごとの帳簿数量・棚卸実数・差分・メモおよび集計サマリ(総件数・変動なし・増加・減少)を返す。<br>・`complete_mobile_stocktake(raw_text, staff_id)` で、単一の `transaction(self.conn)` 内で再検証・全対象品目の時計巻き戻り検査を行った上で、品目順(`code, id` 昇順)に `Reason.ADJUST` の履歴 INSERT(差分 0 もすべて記録。`delta > 0` は参考価格を単価とし、`delta < 0` は `plan_fifo_allocations` で FIFO 引当を記録)・`items.quantity` 更新を行い、最後に `active_stocktakes` から当該クライアントを削除する。途中で 1 件でも失敗した場合は全件ロールバックする。 |
| PC 側の導線と画面構成 | ・「在庫」メニューおよびツールバーに「スマホ棚卸…」(`mobile_stocktake_action`、常時活性)を追加する。<br>・棚卸手続き中のクライアントが 1 件以上ある場合、`MainWindow` の一覧テーブル上部に通知バナー(`📱 スマホ棚卸手続き中: <クライアント名>...` と「スマホ棚卸を開く…」ボタン)を表示する。<br>・`MainWindow` で棚卸手続き中クライアントの品目を 1 件選択している場合、編集・廃止/再有効化・在庫操作アクションを不活性化し、ツールチップに「このクライアントはスマホ棚卸手続き中のため操作できません」を表示する。 |

- カメラによるバーコード / QR コード読み取り

- 廃止品目(`is_active = 0`)のスマホ棚卸シートへの出力
