- ステータス: 実装中
- 作業ブランチ: `feature/v0.3.2-plan`(計画書作成)→ `feature/v0.3.2-label-model-number`(実装・正本統合)
- 基盤とする文書: [ローカル在庫管理アプリ開発計画書](ローカル在庫管理アプリ開発計画書.md)(3.1・3.2・5.1・6.3・6.4・8・9.1 章)

## 1. 目的

- 棚ラベル(`エーワン 72212`)の印字項目に「メーカー型番(`manufacturer_part_number`)」と「用途(`application`)」を追加し、棚や保管容器に貼付したラベルから品目の識別情報と用途を直接確認できるようにする。
- 棚ラベルの全項目を同じ文字サイズにそろえ、用途も他の項目と同等に読みやすい 6 行配置へ見直す。
- 棚ラベル印刷ダイアログ(`LabelPrintDialog`)の品目表にも「メーカー型番」「用途」列を追加し、印刷枚数を指定する際に対象品目の型番と用途を確認できるようにする。
- 上記の改修に伴い、アプリの版数を `0.3.1` から `0.3.2` へ引き上げ、確定した仕様を開発計画書(正本)へ統合する。

## 2. 要件

### 2.1 満たすべき仕様

- 開発計画書 3.1(層構成と依存方向)、3.2(モジュール構成)、5.1(品目)、6.3(画面詳細)、6.4(表示要件)、8 章(テスト方針)、9.1(印刷の基本設計)に従う。
- `core/` と `db/` は変更しない(印刷は UI 層の機能)。`ui/printing/layout.py` は `PySide6` を import しない。
- UI は Service のみを経由し、印刷に必要なデータは既存の `ItemRow`(`InventoryService.list_items()` の結果)から取得する。
- 最小解像度 1366×768 かつ文字サイズ 100%・150% のいずれでも、改修後の `LabelPrintDialog` が画面内に収まり、すべての操作に到達可能であること。
- 印刷の文字サイズは UI の文字サイズ設定とは独立して全行 10pt とし、品名とメーカー型番のみ太字にする。実際の描画先のフォントメトリクスで、6 行が重ならず、上下 3mm の内側余白内に収まることを検証する。
- 次のコマンドがローカル(Windows)と CI(Windows/Linux)で成功すること。
  - `uv sync --locked`
  - `uv run ruff check` / `uv run ruff format --check`
  - `uv run pyright`(`core/`・`db/` は strict、`ui/` は standard でエラー 0 件)
  - `uv run pytest --cov`(Linux は `QT_QPA_PLATFORM=offscreen`)
  - `uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90`
  - `uv run python scripts/check_release_version.py --version 0.3.2`
- 自動テストで実プリンタ・実データの保存先(`%APPDATA%` 等)を使用しない。手動確認も一時保存先と架空データを使用し、試し刷りは自動テストと分けて利用者が行う。

### 2.3 決定事項

| 項目 | 決定 |
| --- | --- |
| ラベルの印字項目と順序 | 上から順に **品名・メーカー型番・用途・管理番号・保管場所・備考** の 6 行固定とする |
| 各行のフォントと縦位置 | 全行 10pt とし、品名とメーカー型番のみ太字、用途・管理番号・保管場所・備考は標準とする。ラベル内側余白は 3.0mm を維持し、行上端をラベル上端から 3.0 / 9.0 / 15.0 / 21.0 / 27.0 / 33.0mm に配置する。詳細は下表のとおりとする |
| 印字形式 | すべての項目は見出し(「型番:」「用途:」等の接頭辞)を付けず値のみを左寄せで印字する。未登録(`None` または空文字)の場合も行を詰めず、各行の縦位置を固定する。用途と備考の CRLF・CR・LF は空白に置換し、ほかの項目の整形や保存値は変更しない。各行は 1 行で `QFontMetrics.elidedText(ElideRight)` により描画幅内へ切り捨てる |
| 配置の検証と不合格時の扱い | 下表の位置は実測前の設計基準とし、300 DPI・1200 DPI の実フォントメトリクスで非重複と上下余白を検証する。収まらない場合は、まず 10pt を維持して位置を再検討する。合意した配置・文字サイズの変更が必要なら利用者へ再確認し、無断の縮小・余白変更・検証省略は行わない |
| 棚ラベル印刷ダイアログの列構成 | `LabelPrintDialog` の `item_table` を 5 列(`["管理番号", "品名", "メーカー型番", "用途", "枚数"]`)に変更する。列のリサイズモードは 列 0(管理番号): `ResizeToContents`、列 1(品名): `Stretch`、列 2(メーカー型番)・列 3(用途): `Interactive`(初期幅は各 140px)、列 4(枚数): `Fixed`(幅 90px)とする。残り幅は品名へ割り当てる。型番・用途が `None` または空文字のときは空欄とし、列 0〜3 のセルは編集不可とする。列 1〜3 のセルには全文をツールチップ(`setToolTip`)で表示し、表で省略表示されても全文を確認できるようにする |
| 版数 | アプリ版数を `0.3.2` に引き上げる(`pyproject.toml`・`uv.lock`・`README.md`)。`SCHEMA_VERSION = 5` は維持する。`README.md` の「v0.3.0 の DB・バックアップは v0.2.0 以前のアプリでは開けません」は、スキーマ版が変わらないため据え置く |

行ごとの描画定義:

| 行 | 項目 | 文字サイズ | 太字 | `top_offset_mm`(ラベル上端からの行上端位置) |
| --- | --- | --- | --- | --- |
| 1 | 品名 | 10pt | あり | 3.0mm |
| 2 | メーカー型番 | 10pt | あり | 9.0mm |
| 3 | 用途 | 10pt | なし | 15.0mm |
| 4 | 管理番号 | 10pt | なし | 21.0mm |
| 5 | 保管場所 | 10pt | なし | 27.0mm |
| 6 | 備考 | 10pt | なし | 33.0mm |

- 行上端はベースラインではない。既存の計算式 `baseline = (slot_y + top_offset_mm) * dpi_y / 25.4 + metrics.ascent()` を維持する。
- 横方向は既存どおりラベル左端から 3.0mm、描画幅は 80.4mm とする。行位置の固定値だけで収まりを判断せず、実際の描画先で文字の上端・下端も検証する。
