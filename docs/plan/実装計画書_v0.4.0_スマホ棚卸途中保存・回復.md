## 1. 目的

- Android スマホで行う一括棚卸の途中状態を `localStorage` に依存せず `IndexedDB` に自動保存し、同じ棚卸シートを開き直して作業を再開できるようにする。
- ブラウザの保存領域が消去・変更された場合に備え、未確認・入力途中でも取得できる専用バックアップと、その読込による回復手段を追加する。
- 空欄などの途中入力を保存した後、復元時にシート全体が初期化される現行の不整合を解消する。結果出力・PC 側確定時の厳格な検証は維持する。
- アプリ版数を `0.3.2` から `0.4.0` へ引き上げ、確定仕様と実機確認条件を開発計画書(正本)へ統合する。

## 2. 要件

### 2.1 基本要件と保証範囲

- 品目データ・CSS・JavaScript を内包する単一 HTML と、外部通信を行わないオフライン方式を維持する。ライブラリやフォントを外部から読み込まない。
- `core/mobile_stocktake.py` の `render_stocktake_html()` を改修の中心とする。`core/`・`db/` の PySide6 非依存、UI → Service → Repository の依存方向を維持する。
- 通常の途中保存・復元に `localStorage` を使用しない。IndexedDB 利用不可時のフォールバックや、旧保存形式の自動移行も追加しない。
- IndexedDB は無制限でも絶対的な永続領域でもない。利用者による消去、容量不足、ブラウザによる消去、OS・ブラウザ更新、ファイルの開き方による保存領域の違いを考慮する。「IndexedDB にすれば将来も必ず復元できる」とは案内しない。
- 自動復元の対応範囲は、実機で確認した端末・ブラウザ・同一 HTML・起動経路に限定する。ファイルの移動・再取得や別ブラウザでの IndexedDB 継続利用は保証しない。
- 保存領域が利用できない場合も入力を継続できる。現在の画面内容を維持し、警告・再試行・途中バックアップを利用可能にする。
- 強制終了直前の未完了変更や、最後のバックアップ取得後の変更は回復できない場合がある。HTML 自体の JavaScript が実行不能になる変更まで回復を保証しない。
- 自動テスト・手動確認では架空データと一時保存先を使い、実データの保存先(`%APPDATA%` 等)を使用しない。

## 3. 設計方針

### 3.1 下書きデータの契約

IndexedDB と途中バックアップで、共通の下書き形式を使用する。結果データとは形式と用途を分離する。

| フィールド | 型・用途 |
| --- | --- |
| `kind` | 固定文字列 `imm-stocktake-draft`。結果 JSON と区別する |
| `v` | 下書き形式の版数 `1`。アプリ版数・SQLite 版数・結果形式の版数とは独立 |
| `session_id` | 現在のシートのセッション ID |
| `client_id` | 現在のシートのクライアント ID |
| `started_at` | 現在のシートに埋め込まれた開始日時(UTC)。シートとの一致確認に使う |
| `items` | 全品目の配列。品目の欠損・余分・重複を禁止する |
| `items[].item_id` | 品目 ID。シートの品目集合と完全一致すること |
| `items[].book_quantity` | シートに埋め込まれた帳簿数量。一致確認用であり、読込で帳簿数量を変更しない |
| `items[].actual` | 実数入力の文字列。空欄や入力途中の値を、数値へ丸めず保持する |
| `items[].note` | メモの未正規化文字列。前後空白や改行も途中状態として保持する |
| `items[].confirmed` | 確認状態の真偽値。復元時に業務入力の正常性を再検証する |
| `items[].badInput` | 数値入力欄の `validity.badInput` に対応する真偽値。不正入力を誤って確認済みにしないために保持する |

- 種別・版数・シート識別情報・品目集合・帳簿数量・各フィールドの型を検証してから、復元候補を作成する。
- 構造検証に失敗した下書きは全体を拒否し、自動的に部分復元・削除・初期値での上書きをしない。
- 構造が正しい下書きは、空欄・小数・範囲外の数量・500 コードポイント超のメモなども途中状態として復元する。業務入力として不正な品目は `confirmed = false` とし、入力エラーを表示する。他の正常な品目は失わない。
- `input[type=number]` が JavaScript に公開しない入力途中の文字列は保存できない。保持対象は入力欄から取得できる `value` と `badInput` とし、非公開のキーストロークまでの復元は保証しない。また、ブラウザ仕様により `actualInput.value = ""` を再設定すると DOM の `actualInput.validity.badInput` は `false` に戻るため、復元後の検証(`updateCardUI()`・`updateOverallProgress()`)は DOM の `validity.badInput` ではなく `state[key].badInput` を参照する。非公開の不正文字列自体は復元後に空欄表示となるが、`badInput: true`(または `actual: ""`)により「入力エラー・未確認(`confirmed = false`)」として安全に復元する。
- 結果出力時は既存の `validateItemState()` 等で再検証し、実数 `0〜1,000,000` の整数、メモは前後空白除去後 500 Unicode コードポイント以内、全品目確認済みという条件を維持する。
- 下書きを結果として PC に渡した場合は、結果用の `entries` を設けないことに加え、`parse_stocktake_payload()`(`_validate_payload_object()`)で `kind == "imm-stocktake-draft"` を検出して「これは途中保存用の下書きデータです。全品目を確認して出力した棚卸結果データを読み込んでください」という専用の `ValidationError` で明確に拒否する。

### 3.2 IndexedDB の保存構造と非同期制御

- DB 名は `imm_stocktake`、DB 版数は `1`、object store は `drafts`、主キーは `session_id` とする。
- 保存レコードは `session_id`・`storage_revision`・`draft` を持つ。`draft` は 3.1 の共通形式とし、内外の `session_id` の一致も検証する。`storage_revision` は保存先の競合検出用とし、バックアップへ含めない。
- 数量入力・メモ入力・増減ボタン・帳簿通り確認・明示確認・確認解除・リセットの各変更で、直ちに保存要求を発行する。入力表示は保存完了を待たず更新し、長い debounce や終了イベントだけに保存を依存させない。
- 保存処理は単一の書込制御に集約する。変更番号と保存対象のスナップショットを管理し、処理中に追加された要求は最新状態へ集約する。古い変更の完了で、最新変更を保存済みにしない。
- `put` の要求成功ではなく、書込トランザクションの `complete` を保存完了とする。`error`・`abort` を処理し、トランザクションが有効である必要のある区間に無関係な非同期処理を挟まない。
- 同一セッションを複数タブで編集した場合は、同一 readwrite トランザクション内で読み取った `storage_revision` と期待値を比較する。不一致なら上書きせず、警告とバックアップ退避を可能にする。自動マージはしない。
- IndexedDB の API 取得・open の同期例外、読込・書込・容量不足・接続終了を処理する。`blocked`・`versionchange` も扱い、必要な接続を閉じる。
- open・初回読込は 10 秒で待機を打ち切り、永久に入力を停止しない。処理世代を区別し、打ち切り後の遅い成功通知で state を置き換えない。遅れて開いた不要な接続は閉じる。
- 起動時は復元処理の完了・失敗判定まで入力・リセット・バックアップ読込を無効にし、「読込中」と表示する。復元前の初期状態を先に保存しない。
- 初回読込が失敗した場合は「既存データなし」とみなさない。再試行時に保存先を再読込し、異なる既存状態があれば、保存データの復元と現在の画面による置換の選択を利用者に確認する。選択までは保存先を変更しない。
- バックアップ読込・リセットでは旧待機スナップショットを無効にし、実行中の書込を完了または abort 処理してから新しい状態を保存する。古い非同期処理が置換後の state や保存状態表示を変更しない。
- `visibilitychange`・`pagehide` による保存は補助とする。終了イベントで非同期保存の完了を保証しない。`navigator.storage.persist()` の成功を必須条件や保証の根拠にしない。

### 3.3 保存状態・失敗時の操作

| 状態 | 表示と操作 |
| --- | --- |
| 読込中 | 復元対象の確認中であることを表示し、入力等を一時的に無効にする |
| 保存中 | 最新変更の保存が未完了であることを表示する。入力は継続できる |
| 保存済み | 最新変更に対応するトランザクション完了後にのみ表示する。電源断等への絶対保証を意味しない |
| 保存失敗 | 「途中保存できません。画面を閉じないでください。」等の警告を常時表示し、「再試行」と途中バックアップを利用可能にする |
| 復元不一致・破損 | 保存内容を採用しない理由を表示し、初期表示から作業する場合も既存レコードを黙って置換しない。明示リセットまたは検証済みバックアップの読込を回復手段とする |
| 別タブ更新 | 保存競合を表示し、自動上書きを停止する。現在の入力のバックアップ退避と、他タブを閉じた後の再読込を案内する |

- 保存失敗の警告は最新状態の保存成功まで消さない。再試行開始だけで成功表示に変えない。
- 保存失敗を理由に画面内容を初期化しない。結果出力は既存の全件確認・正常入力条件に従い、IndexedDB の成否だけでは禁止しない。
- 常設表示は小さくし、スマホ縦横画面(特に横画面 `844×390`)で入力欄・既存ボタンの到達性を損なわない。保存状態バッジ(読込中・保存中・保存済み・保存失敗)は固定ヘッダ(`#app-header`)内にコンパクトに配置し、途中バックアップの保存・読込・テキスト入出力などの詳細操作は `<details>` 等による開閉領域またはスクロール領域側(完了パネル付近)に配置して、固定ヘッダを過度に高くしない。
- バックアップ読込の置換確認、明示リセットの確認、および初回読込失敗後の再試行時に既存保存データと現在画面のどちらを採用するか選ぶ確認は、モバイル環境での `window.confirm()` 抑止や 2 択の意味の分かりにくさを避けるため、HTML 内のインライン確認パネル(明示的な実行ボタン・キャンセルボタンを持つ UI 要素)で行う。

### 3.4 途中バックアップ

- 「途中データを保存」「途中データを読み込む」を追加し、未確認・入力エラーを含む現在の画面状態を扱えるようにする。IndexedDB の接続・保存成功には依存させない。
- 保存内容は 3.1 の下書き JSON とし、ファイル名は `棚卸途中_<安全化クライアント名>_<シート開始日時>_<session_id先頭8桁>.json` とする。既存のファイル名安全化処理に従う。
- 保存は利用者の明示操作でのみ実行する。入力ごとの自動ダウンロードや、許可なく既存ファイルを書き換える処理は行わない。
- 既存の Blob・download の実装パターンを再利用する。ダウンロード開始と実際のファイル保存成功は区別し、検知できない保存完了を断定しない。
- ダウンロード不可時には同じバックアップ JSON を表示して手動コピーできるようにし、貼付読込も用意する。新たな Base64 等のプロトコルは追加せず、結果テキスト用の表示・読込と区別する。
- ファイル読込には File API を使用する。読込・解析・検証中と失敗時は、現在の画面と保存レコードを変更しない。任意の HTML・JavaScript を実行せず、表示には `textContent`・`value` を使う。
- バックアップのシート識別情報と全品目を検証し、対象クライアント・開始日時・復元予定の確認件数を表示する。「現在の入力全体を置き換える」ことの確認後に適用する。キャンセルは無変更とする。
- 適用後は新しい状態を IndexedDB に保存要求する。保存失敗時も復元した入力は画面に残し、未保存警告と再バックアップを利用可能にする。バックアップ元の保存競合番号は引き継がない。
- 「初期状態にリセット」は確認を挟み、対象セッションだけを帳簿数量・全件未確認へ置き換える。他セッションやブラウザ全体のデータは削除しない。
- 途中バックアップは平文で保存される。利用者による保管・削除が必要であり、結果出力後も自動削除しないことを README に記載する。

### 3.5 旧シートとバージョンの扱い

- v0.4.0 のインストールだけでは、配布済みの旧 HTML の動作は変わらない。旧手続きは旧 HTML で完了し、v0.4.0 の新規シートから新方式を使用する。
- 新方式へ切り替えるためにシートを再出力しても、旧入力は引き継がれない。再出力によるセッション変更・旧結果無効化という既存仕様を維持する。
- `pyproject.toml`・`uv.lock`・README の版数例を `0.4.0` にそろえる。`SCHEMA_VERSION = 5`、結果ペイロード `v: 1`、下書き形式 `v: 1`、IndexedDB 版数 `1` を混同しない。

## 4. 実装タスク

## 7. 技術資料

- [MDN: IDBFactory.open()](https://developer.mozilla.org/en-US/docs/Web/API/IDBFactory/open): 非同期の open、blocked・versionchange の扱い
- [MDN: IDBTransaction complete event](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event): トランザクション完了による保存成功の判定
- [MDN: Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria): 保存領域の分離、容量不足、ブラウザによる消去、永続性の限界

これらは API の設計根拠として参照し、対象 Android の実際のローカル HTML 起動経路での動作保証には第 6 章の実機確認を用いる。
