# 備品在庫管理アプリ

設備管理現場で使う備品の在庫を、ローカル PC で管理する PySide6 デスクトップアプリです。品目・関連マスタ、入出庫履歴、低在庫通知、CSV 出力、ダッシュボード、印刷、バックアップなどを提供する計画です。

## 対象環境

- Windows 10 以上
- Linux (Python 環境を用意して実行)
- Python 3.13 以上
- パッケージ管理に uv を使用

## 開発環境の準備

Python 3.13 と uv をインストールした後、リポジトリのルートで依存関係を同期します。

```sh
uv sync
```

## 検査・テスト

次のコマンドは CI でも実行します。依存関係の再現性を確認する場合は `uv sync --locked` を使います。

```sh
uv sync --locked
uv run playwright install chromium
uv run ruff check
uv run ruff format --check
uv run pyright
uv run pytest --cov
uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90
```

Linux CI では Chromium とシステム依存関係を `uv run playwright install --with-deps chromium` で準備します。

## アプリの起動

Python 3.13 と uv をインストールした後、リポジトリのルートで依存関係を同期して起動します。

```sh
uv sync --locked
uv run python -m inventory_manager_mini
```

### Windows

PowerShell で実行します。

```powershell
uv sync --locked
uv run python -m inventory_manager_mini
```

### Linux

Qt の実行に必要な OS パッケージをインストールしてから起動します。

```sh
sudo apt-get update
sudo apt-get install --yes libegl1 libgl1 libxkbcommon0 libdbus-1-3 libfontconfig1 libxcb-cursor0
uv sync --locked
uv run python -m inventory_manager_mini
```

通常起動では `QT_QPA_PLATFORM=offscreen` を設定しません。

## Windows 配布版のインストール

GitHub Release からインストーラーと同じ版の `.sha256` ファイルを取得します。インストーラーの
起動前にハッシュを照合してください。

```powershell
$installer = '.\inventory-manager-mini-0.4.0-setup.exe'
$expected = ((Get-Content "$installer.sha256" -Raw).Trim() -split '\s+')[0].ToLowerInvariant()
$actual = (Get-FileHash -LiteralPath $installer -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw 'SHA256 が一致しません。インストーラーを実行しないでください。' }
'SHA256 が一致しました。'
```

インストーラーでは「全ユーザー」または「自分のみ」を選択できます。署名のないインストーラーの
ため SmartScreen が警告する場合は、公式 Release から取得したことと SHA256 の一致を確認した上で、
「詳細情報」から実行します。

## アンインストールとデータ

アンインストールではアプリ本体だけを削除し、データとログは保持します。既定の保存先は次のとおりです。

- DB・バックアップ・表示設定・多重起動ロック: `%APPDATA%\inventory-manager-mini`
- ログ: `%LOCALAPPDATA%\inventory-manager-mini\Logs`

完全に削除する場合は、アプリを終了して必要なバックアップを取った後、エクスプローラーのアドレス欄に
`%APPDATA%\inventory-manager-mini` と `%LOCALAPPDATA%\inventory-manager-mini` をそれぞれ入力し、
両フォルダーを手動で削除してください(後者には `Logs` が含まれます)。環境変数
`INVENTORY_MANAGER_MINI_DATA_DIR` で保存先を変更していた場合は、その指定先も別途確認してください。

## Windows でのローカルビルド

Windows x64、Python 3.13、uv、および Inno Setup 6.7.3 が必要です。ビルドスクリプトは ISCC の実版を
検査します。標準のインストール先以外にある場合は `-IsccPath` で実際に使う `ISCC.exe` を指定します。

```powershell
uv sync --locked
uv run python scripts/fetch_dependency_sources.py
.\packaging\build.ps1 -Version 0.4.0
```

PowerShell の実行ポリシーで `build.ps1` が拒否される場合は、`pwsh -File packaging/build.ps1 -Version 0.4.0` のように
実行するか、利用者の判断で現在のセッションだけ実行ポリシーを変更してください。

検証用 rc ビルドでは接尾辞を別に指定します。

```powershell
.\packaging\build.ps1 -Version 0.4.0 -Suffix '-rc1'
```

成果物は毎回異なるビルド ID の `dist/releases/<ビルドID>/` に出力されます。そこにはインストーラー、
アプリソース ZIP、構成一覧と、それぞれの SHA256 ファイルが含まれます。ビルド途中で失敗した場合は
非ゼロ終了となり、その回の成果物は確定されません。古い `dist/releases/` の内容を今回のビルド結果と
して使用・配布せず、コマンドが成功時に出力したパスだけを対象にしてください。依存ソースを取得していない
ローカル検証ビルドの `-sources.zip` は、対応ソースの要件を満たさないため配布に使いません。

アプリ・インストーラーのアイコンを指定する場合は `packaging/app.ico` に配置してからビルドします。
ファイルがない場合もビルドでき、その場合は既定のアイコンを使用します。

## 凍結版の確認と保存先の保護

開発 PC では、インストーラーの最後に表示されるアプリ起動チェックを外してください。起動前に一時保存先を
設定し、同じ PowerShell からインストール先の exe を直接実行します。

```powershell
$testData = Join-Path $env:TEMP ("inventory-manager-mini-" + [guid]::NewGuid().ToString('N'))
$env:INVENTORY_MANAGER_MINI_DATA_DIR = $testData
Write-Output "検証用保存先: $env:INVENTORY_MANAGER_MINI_DATA_DIR"
$installDir = Join-Path $env:LOCALAPPDATA 'Programs\Inventory Manager mini'
& (Join-Path $installDir 'inventory-manager-mini.exe')
```

全ユーザーでインストールした場合は `$installDir` を実際のインストール先に変更してください。
起動後、「バージョン情報」に表示される DB パスが `$testData\inventory.db` であることを確認します。
開発 PC ではインストーラーからの起動や、復元後の再起動への環境変数継承を検証しません。

インストーラー起動・復元後の再起動への保存先継承、および環境変数を設定しない既定保存先は、実データのない
Windows Sandbox または新規 VM でのみ確認してください。継承確認では一時保存先を設定したシェルから
インストーラーを起動し、各起動後に DB パスを確認します。既定保存先の確認は空の検証ユーザーで環境変数を
解除して行い、`%APPDATA%` 配下に既存データがある環境では起動しないでください。

## 基本操作

### 在庫操作

初回は「マスタ」メニューでクライアント・発注主体・担当者などを登録し、「品目」メニューの「新規」から品目を登録します。品目を一覧で選択し、「在庫」メニューまたはツールバーから入庫・出庫・返品・廃棄・棚卸を選びます。右クリックメニューからも操作できます。在庫操作は有効な品目を選択しているときに利用できます。

品目の編集でカテゴリを変更して保存すると、管理番号は変更後のカテゴリで再採番されます。印刷済みの棚ラベルは再印刷してください。

操作ごとに担当者を選択します。出庫では使用先が必須です。入庫の単価は空欄にすると現在の参考価格が使われます。参考価格と異なる単価を入力した場合は、確認画面で参考価格を更新するか選べます。「キャンセル」では入庫を記録しません。出庫・廃棄の原価は入庫単価の古いロットからFIFOで計算され、操作画面に見積原価と単価未登録数量が表示されます。参考価格は出庫・廃棄の原価には使われません。棚卸では実数を入力し、現在数との差分が履歴に記録されます。

### 履歴と取り消し

品目を選択して「品目」メニューの「履歴」、ツールバーの「参照」グループ、または右クリックメニューから履歴を開きます。一覧のダブルクリックでも開けます。履歴は新しい順に表示されます。表示件数は 300 件または 500 件から選び、「前へ」「次へ」でページを移動します。期間欄では全期間・年次(年度単位)・月次(年度内の選択した月)に絞り込めます。期間の判定はローカル暦で行い、取り消し行は取り消された元の行の日時で判定します。取り消し後は、取り消し行の追加で元の行が含まれるページを表示し、元の行を選択します。

取り消し可能な履歴行を選び、「取り消し…」から担当者を指定して確定します。取り消しは元の履歴を削除せず、反対符号の履歴を追加します。取り消せない行ではボタンが無効になり、理由がツールチップに表示されます。すでに出庫・廃棄・返品・棚卸減少で消費した入庫ロットは、その消費操作を先に取り消すまで取り消せません。消費操作を取り消すと元と同じロット引当が戻ります。取り消し後も、入庫時に更新した参考価格は元に戻りません。

### 低在庫アラート・販売ページ

品目の数量が閾値以下になると、一覧の行が着色され、「アラートパネル」に品目と低在庫件数が表示されます。低在庫品目がある状態で起動すると、通知ダイアログも表示されます。パネルは起動時に表示され、「表示」メニューの「アラートパネル」で隠したり再表示したりできます。在庫操作や閾値変更、品目の廃止・再有効化後は自動で更新されます。廃止品目は低在庫一覧に含まれません。

アラートパネルの行をダブルクリックすると、一覧の検索・絞り込みが解除されて該当品目が選択されます。販売ページ URL が登録されている行では「販売ページ」ボタンから既定のブラウザーを開けます。URL が未登録の場合、ボタンは無効です。品目の編集画面のほか、一覧で品目を選択して「品目」メニュー、ツールバー、右クリックメニューからも販売ページを開けます。URL がない品目では各操作が無効です。

### CSV 出力

「ファイル」メニューまたはツールバーの「CSV 出力」から在庫一覧・履歴を保存できます。在庫一覧は画面の検索・絞り込み条件を反映します。

全品目の履歴を出力する場合は、出力条件ダイアログでクライアント(「すべて」または登録済みのクライアント。無効化済みのクライアントも選べます)と期間(全期間・年次・月次)を指定します。両方の条件を満たす履歴だけを出力し、クライアントは履歴に記録されたもので判定します。品目ごとの履歴画面からの出力は、画面で選択中の期間に一致するその品目の全履歴を出力します(表示中のページだけではありません)。いずれも出力は古い順です。期間の判定はローカル暦で行い、取り消し行は取り消された元の行の日時で判定します。取り消し行の「日時」列には取り消しを実行した日時が出力されます。CSV は Excel で開ける UTF-8 BOM 付きで、日時はローカル時刻です。

### ダッシュボード

「表示」メニューの「ダッシュボード」から非モーダルの画面を開きます。クライアント・発注主体・カテゴリ・品目を独立して絞り込め、条件は AND で適用されます。カテゴリを選ぶと子孫カテゴリの品目も対象になり、過去履歴は品目の現在のカテゴリで集計します。品目は管理番号・品名の一部から候補を検索できます。無効化済みのクライアント・発注主体・品目も過去履歴の確認用に選択できます。月次では年度を選び、年次では利用可能な全年度の推移を表示します。

内訳軸はクライアント・発注主体・カテゴリ・品目のチェックボックスで、任意に組み合わせられます。「グラフ」タブには入庫数・出庫数の数量グラフと支出額の金額グラフ、「内訳」タブには集計行、「廃棄」タブには廃棄実績のある行が表示されます。表にはカテゴリと「管理番号 品名」が表示されます。

CSV は現在表示中の内訳行を出力し、列は「年度/月、クライアント、発注主体、カテゴリ、管理番号、品名、入庫数、出庫数、支出額、単価未登録数量、廃棄数、廃棄額」の 12 列です。各内訳軸が未指定の列は「(すべて)」になります。PNG は「グラフ」タブで保存でき、スクロール範囲を含む両方のグラフを 1 枚に出力します。集計がまだ取得できていない間は出力できません。

### スマホ棚卸

事務所 PC のネットワーク外にあるクライアント現場へ Android スマートフォンを持ち出し、ブラウザ上のボタン操作で月次棚卸を行い、帰社後に PC へ一括反映します。アプリはネットワーク通信やポート待受を行わず、品目データと操作画面を 1 つにまとめた HTML ファイルの受け渡しと、結果の貼り付け・ファイル読込で連携します。

使い方の流れ:

1. 出発前に「在庫」メニューまたはツールバーの「スマホ棚卸…」を開き、「① 出発前」タブでクライアントとシート作成担当者を選んで「棚卸シート(.html)を作成して保存…」を実行します。対象クライアントの有効品目すべてが対象です。
2. 作成した HTML をスマートフォンへ転送します。Gmail または Quick Share で送り、Files アプリから Chrome で開く経路を確認済みです。簡易ビューアで開いた場合は画面の案内に従って Chrome で開き直してください。
3. 現場で品目ごとに「帳簿通りで OK」、または数量(`-10` / `-1` / 直接入力 / `+1` / `+10`)を入力して「この実数で確認」を押します。メモも入力できます。数量やメモを変えると未確認に戻ります。全品目が確認済みで入力に誤りがない場合だけ結果を出力できます。
4. 結果は「結果テキストをコピー」(`IMM1:...:END`)して Gmail などで自分宛に送るか、「結果ファイル(.json)を保存」して PC へ渡します。コピーや保存ができない場合は「結果テキストを表示」から長押しでコピーできます。
5. 帰社後に「② 帰社後」タブで結果テキストを貼り付けるか、結果ファイルを読み込み、差分プレビューを確認します。確定担当者を選んで「この内容で棚卸を一括確定する」を押すと、全品目の棚卸が 1 回の操作として記録されます。入力を変更した場合は、もう一度プレビューするまで確定できません。メールの折り返しや引用付き返信でも取り込めます。異なる結果が複数含まれる場合は、1 件だけ貼り付けてください。

注意事項:

- 棚卸手続き中のクライアントは、品目の登録・編集・廃止、在庫操作、履歴の取り消し、クライアントの無効化・削除、シート作成担当者の削除ができません。解除は一括確定または「① 出発前」タブの「棚卸を中止」で行います。他のクライアントの操作と閲覧・CSV 出力・印刷・バックアップは通常どおりです。
- シート HTML は既存ファイルへ上書きできません。同じクライアントでシートを再作成すると前のシートは無効になり、その結果は取り込めません。
- 途中保存はブラウザの保存領域を使います。再開は、同じ端末の Chrome で同じファイルを開き直す条件で確認済みです。ファイルの移動・再取得や別アプリからの起動では復元されない場合があるため、現場では画面を閉じずに作業してください。保存できない場合はシート上に警告が表示されます。
- 復元すると棚卸手続きの状態も復元元のとおりになり、持ち出し中のシートの結果は取り込めなくなる場合があります。
- v0.3.0 の DB・バックアップは v0.2.0 以前のアプリでは開けません。

### データ保存先

既定では OS ごとのユーザーデータ領域に保存します。保存先を変更する場合は、起動前に `INVENTORY_MANAGER_MINI_DATA_DIR` を設定してください。DB・バックアップ・多重起動ロックは指定したディレクトリ直下に、ログはその `logs/` 配下に作成します。

PowerShell:

```powershell
$env:INVENTORY_MANAGER_MINI_DATA_DIR = "$env:LOCALAPPDATA\InventoryManagerMini"
uv run python -m inventory_manager_mini
```

Linux:

```sh
export INVENTORY_MANAGER_MINI_DATA_DIR="$HOME/.local/share/inventory-manager-mini"
uv run python -m inventory_manager_mini
```

この環境変数は、テストや一時的な動作確認で通常の保存先とデータを分ける場合にも使えます。

### バックアップ・復元

「ファイル」メニューの「バックアップ」で保存先を選んで手動バックアップを作成できます。「復元」ではバックアップ DB を検査し、内容と移行情報を確認してから現行 DB を置き換えます。復元前に自動バックアップを作成し、成功後はアプリを再起動します。復元しても端末ごとの表示設定は変わりません。

### 表示設定

「ツール」メニューの「設定」から年度開始月、フォント、文字サイズ(90 / 100 / 125 / 150%)を変更できます。フォントと文字サイズは OK 後に即時反映され、再起動後も保持されます。「既定に戻す」はフォントと文字サイズのみを OS 既定・100% に戻し、年度開始月は変更しません。表示設定はデータ保存先の `ui_settings.json` に保存され、バックアップ・復元の対象外です。

### Linux のヘッドレステスト

GUI を表示できない環境でテストする場合は、通常起動とは分けて次を実行します。

```sh
QT_QPA_PLATFORM=offscreen uv run pytest --cov
uv run coverage report --include="src/inventory_manager_mini/core/*,src/inventory_manager_mini/db/*" --fail-under=90
```

### 性能テスト

性能テストは既定のテスト実行ではスキップされます。明示的に実行する場合は次を使います。5,000 件の品目と 100,000 件の履歴を使い、起動・検索・絞り込み・ソート・レポート・FIFO出庫の保存と一覧再描画を計測します。

```sh
uv run pytest --run-perf tests/test_performance.py
```
